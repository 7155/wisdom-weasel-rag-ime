# Agent Lab 工作台交互原型

> LP-S14 已修正通用前端方案：本原型只作为知识问答项目的一种模板参考。实际产品由 Agent 决定各项目成果与展示结构，不能把这里的固定八工作区和业务字段用于全部项目。

这是 [Lab 整体设计](../../LAB_PRODUCT_DESIGN.md#7-前端信息架构) 的可操作设计稿，用于检查用户如何从描述/材料进入，查看证据、修改方法、比较候选、试用并准备交付。

当前是独立静态原型。所有材料、运行、费用、判定和交付检查都是明确标注的设计示例；没有连接真实 Pi Session、Golden/实验服务、Provider、项目文件或 App 打包。

## 打开

在仓库根目录运行：

    python3 -m http.server 55724 --bind 127.0.0.1 --directory control-center-web/docs/pawos/prototypes/lab-workbench

随后打开 [本地原型](http://127.0.0.1:55724/)。这是静态预览服务，不是 PAW Gateway。已启动同一服务时无需重复启动。

入口为 [index.html](index.html)，样式为 [workbench.css](workbench.css)，交互为 [workbench.js](workbench.js)。不需要安装依赖或调用模型。原型状态保存在当前浏览器的专用 localStorage 项目中；顶部“重置演示”会恢复示例。

## 本轮结构

- 稳定项目导航承载概览、材料与环境、任务与标准、实验探索、方法与代码、版本比较、应用试用、交付与导出。
- 当前成果占主区；Lab 引导和对象详情共用可收起的辅助区。
- 实验关系图表达候选的父版本和改动分支，点击后可打开实际方法内容和差异。
- 持续可见的运行条记录本轮身份、完成数与控制；详细事件可以展开。
- 浏览候选、比较候选、试用版本和交付候选各有自己的选择，查看其他对象不替换已选交付版本。
- 窄窗收起辅助区，必要时单独打开。代码与表格保留自己的滚动区域；全页面不缩小字号。

Flowith 的分支画布用于组织不同改法及其来路；Braintrust 的对象联动和任务比较、Opik 的证据到改动、JupyterLab 的专业工作区也进入了设计取舍。具体官方来源与能力边界统一见 [参考取舍](../../LAB_PRODUCT_DESIGN.md#14-参考取舍与设计完成边界)。

用户已明确由助手决定当前 Lab 设计（LP-S13）。本原型不依赖之前的布局选择页，也不要求额外选择设计 Skill 或工具。

## 建议走一遍的路径

1. 工作概览查看目标和当前问题；也可以点“新项目”，填写描述与路径，观察真实读取之前的待连接状态。
2. 在版本比较选择候选 01，筛选“仅退化”，打开 Q-06 的业务标准、输出和执行证据。
3. 在方法与代码查看候选 02 相对候选 01 的差异，编辑文件并保存为新候选。
4. 在实验探索运行该候选。底部可停止；页面刷新会保存已完成项并显示中断，继续复用该次演示。
5. 对比原版与新候选。汇总之外，可以按任务查看改善和退化；不同标准的实验不能直接给出比较结论。
6. 切到应用试用，针对同一个问题切换版本，查看业务体验。
7. 明确交付候选，演示最终验收，并分别检查 PAW App 与独立 Web 应用的交付结构。
8. 在页面底部选择材料缺口、运行中断或导出失败的检查场景，观察恢复入口和已有成果保留情况。

“运行当前候选”推进固定的六条示例任务，结果由原型数据决定，不用于评估用户编辑的真实效果。“下载清单示例”只生成带 prototype 标记的 JSON，不是可运行 App。

## 当前验证记录

验证日期：2026-09-06。以下均为该静态原型的浏览器交互检查。

| 检查 | 已观察结果 |
| --- | --- |
| 八个工作区 | 导航可达，各自展示目标内容和主要操作 |
| 新项目接入 | 描述/路径形成草稿；未连接时不混入示例任务数、材料或成绩 |
| 方法编辑 | 保存形成候选 04，保留父版本和原版/候选 01 的历史结果 |
| 退化分析 | 候选 01 的“仅退化”筛选定位到 Q-06，呈现原版与候选的不同业务输出 |
| 运行失败与继续 | 演示在 2/6 处失败；继续使用同一运行编号，从第 3 条完成至 6/6，没有重复前两条 |
| 主动停止 | 停止后不再继续推进，保留原运行编号与已完成计数 |
| 刷新恢复 | 2/6 时刷新，仍为同一运行编号与 2/6；呈现已中断而非继续声称运行 |
| 试用版本 | 试用页引用所选候选，并展示对应的固定示例答复 |
| 双目标交付 | 最终验收演示后，两个目标分别记录状态；独立目标失败可以重试 |
| 浏览与交付选择 | 查看候选 01 不替换已选的候选 04 交付记录 |
| 标准版本 | 编辑并保存为 v2，旧原版记录保留 v1；比较页进入不可比较状态，重跑原版后才恢复同条件比较 |
| 空筛选与键盘定位 | 无退化时明确显示空筛选说明；Cmd+K 搜索 Q-06 后打开对应任务证据 |
| 布局 | 已检查 1280px 桌面、760px 窄窗及 390px 试用；后两者 documentWidth 等于 viewport，没有全页面横向溢出 |
| 脚本 | Node 语法检查通过；上述浏览器流程未观察到脚本错误 |

这些检查只证明原型交互；不构成生产 Lab、已安装 PAW、真实优化收益或独立 App 可运行的验收。

## 后续实现连接点

本原型刻意不引入另一套 Agent 执行器。下一步把可用交互接到 [整体设计的所有权与实施顺序](../../LAB_PRODUCT_DESIGN.md#9-架构与所有权)：

- 项目、标准、方法、候选、实验和交付使用服务端版本身份。
- 引导复用 Pi Session，并与页面操作调用同一组业务命令。
- 运行条与恢复读取真实事件、任务结果和控制回执。
- 来源/轨迹、代码差异、费用和比较均使用真实对应对象。
- PAW 与独立目标各自产生实际文件、启动入口和目标环境检查。

自由停靠、完整图编辑、多项目持久管理、真实聊天和生产后端绑定不属于此原型已经完成的范围。

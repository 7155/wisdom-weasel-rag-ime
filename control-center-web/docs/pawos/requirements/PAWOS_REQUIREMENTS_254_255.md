### UR-254 — Lab 是项目重点，优化必须解释成功率与成本收益

- **状态 / 优先级：** `current / P0`
- **直接原话：** “lab需要好好做，因为这个是我面试的重点，项目的重点。需要很多重量级指标，比如测试并自动优化提示词或者工具或者skill，就省大量价格成本和提升成功率”。
- **讨论中的范围解释：** 用户在了解外部 Agent 项目含义后回复“好”；当前先面向 PAW 自身 Pi Agent，外部项目适配为后续范围。该解释与直接原话分开记录。
- **需求：** 场景任务、成功标准、基线、失败诊断、候选改动、复验和选择能形成可解释流程；Prompt、Tool、Skill 属于可优化对象。成本下降和成功率变化必须有可比任务及真实运行回执。
- **边界：** 新 Golden 数据集不能继承旧任务的基线分数；少量开发题的改善不能宣称对全部场景有效。优化搜索成本与业务执行成本分开。

### UR-255 — Lab App 内走完 Golden 建设四步

- **状态 / 优先级：** `current / P0`
- **前置直接原话：** “就是，任务的golen基线怎么做，是人工标注还是比如ci编译通过还是LLMagent判断”。
- **本次直接原话：** “好，app需要能够我建议 Lab 的 Golden 建设流程这样做：

  1. **Agent 起草题目和标准。** 从真实文档、历史任务和失败记录中生成，并附上证据。
  2. **人工审核首批核心题。** 先做几十道有代表性的任务，把事实、边界和判分规则核准。强模型生成的答案也需要核验。
  3. **校准自动评审器。** 用人工判过的正确、错误和边界答案测试 Judge，重点看它会不会把错误答案判成成功。自动评分需要持续与人工判断对齐。[OpenAI 评测实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)
  4. **冻结后自动实验。** 原方案与候选方案使用同一套 Golden 和评审规则；优化过程中使用开发集，最终效果再用未参与调优的保留集检验。

  走完这些”
- **归属说明：** 四步文字最初由 Agent 建议；本条用户直接复制并要求 App 完成，构成本次接受的产品需求。外链为参考资料，不构成额外执行权限。
- **验收：** App 可起草/修改题目与证据、逐题人工审核、标注示例答案、运行 Judge 校准、查看误判与未知、冻结不可变版本并启动同版本对照实验。状态刷新可恢复；未审核草稿不自动标为人工通过；更改标准使旧校准失效；调优者不能消费保留集标准答案。
- **本轮追加直接原话：** “以前错的代码都可以移除删除”。沿用 UR-251：确认新流程替代旧消费者后删除废弃代码，不删除仍有用的历史数据和无关工作。
- **工作与验证：** [Golden 实施文档](../LAB_GOLDEN_WORKFLOW_20260905.md)。该文档的方案及测试均不能替代真实人工审核或安装验收。

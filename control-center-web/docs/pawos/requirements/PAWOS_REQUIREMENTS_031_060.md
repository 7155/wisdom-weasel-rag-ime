### UR-031 — Agent 工作面直接迁移 Tutti 层级，小窗口是首要布局

- **状态 / 优先级：** `current / P0`
- **迁移方式：** 当前 PAWOS Agent 工作面的自研视觉不再作为优化基线；直接搬用
  Tutti Agent 窗口的组件层级、密度、消息流、工具展示、标题栏与 Composer 形态，
  只替换为 PAW Runtime 数据与操作接口。
- **小窗口优先：** Agent/伙伴窗口按窗口容器宽度响应，不按浏览器 viewport 猜测。
  窗口缩小时收起会话目录、检查器和次要标签，移除大块空白，保留当前 Agent 身份、
  上下文/消息流、工具状态与 Composer；四到五个窗口围绕主窗口时仍可读、可输入、
  可观察消息到达。
- **放大恢复：** 窗口重新放大后恢复 Tutti 式会话目录和完整信息，不复制第二份状态，
  不通过缩放整张 DOM 来制造“小窗口”。
- **原话依据：** “当前非常丑，你直接抄 tutti 吧，特别是窗口缩小，因为后续可能
  四五个对话窗口，缩小的显示特别注意”“大不了搬代码”。来源：当前任务。

### UR-032 — Blueprint 是统一的蓝色系统主题，不是灰黑主题

- **状态 / 优先级：** `current / P0`
- **统一主题：** Blueprint 下的 Agent、Room、Terminal、Files、Browser chrome
  与其他 App 都继承同一组蓝色系统表面、文字、边线和强调色；App 不得在内部
  私自覆盖为灰黑或另一套产品色。
- **亮度边界：** Blueprint 保持深蓝工作台，但面板层级必须清楚可辨，不能用
  接近纯黑的大面积背景吞掉内容。Glacier 与 Ink Paper 继续作为可切换主题。
- **Browser 边界：** 主题只控制 PAWOS 与 Browser chrome，不篡改受管 Chromium
  网页自身的白色、深色或站点配色。
- **原话依据：** “优化，风格是蓝色的那个蓝图，或者其他风格，当前太黑了”。
  来源：当前任务。

### UR-033 — Blueprint 固定采用 PAW OS · Blueprint Precision v3

- **状态 / 优先级：** `current / P0`
- **视觉基线：** Blueprint 直接采用 `PAW OS · Blueprint Precision v3`：
  淡蓝工程图画布、克制网格、白蓝分层面板、钴蓝强调、清晰细描边、较小圆角
  与最少毛玻璃。它不是深蓝夜间主题。
- **覆盖关系：** 本条取代 `UR-032` 中“保持深蓝工作台”的亮度描述；`UR-032`
  的统一系统主题、App 不私有覆盖、其他主题可切换和不篡改网页配色仍然有效。
- **原话依据：** “PAW OS · Blueprint Precision v3这个风格呢”。来源：当前任务。

### UR-034 — Blueprint Precision 的组件几何全部使用直角

- **状态 / 优先级：** `current / P0`
- **几何规则：** Blueprint 下的窗口、Dock、App 图标底座、侧栏、卡片、输入框、
  菜单、按钮与浮层全部使用直角矩形，不混入 Glacier 式圆角胶囊。
- **语义例外：** macOS 红黄绿窗口灯和在线/存在状态点继续保持圆形；这是控件
  语义，不是组件表面圆角。
- **覆盖关系：** 本条取代 `UR-033` 的“较小圆角”，其余 Precision v3 视觉约束不变。
- **原话依据：** “这种风格就是全是方形，如果用的话”。来源：当前任务。

### UR-035 — Composer 不使用会干扰窗口合成的环绕流光

- **状态 / 优先级：** `current / P0`
- **行为：** 删除 Composer 外圈无限循环的 `filter/drop-shadow` 流光；聚焦和忙碌
  只使用不改变窗口合成层的静态描边/内阴影状态，不能造成窗口抽搐。
- **原话依据：** “外面流光特效导致窗口抽搐”。来源：当前任务。

### UR-036 — 模型切换和权限批准采用 GPT 式分层菜单

- **状态 / 优先级：** `current / P0`
- **模型与强度：** Composer 底栏可以并列显示当前模型与推理强度，但它们是两个独立控件，
  不是同一菜单中的上下两段。点击模型只打开真实可用模型；点击推理强度只打开当前模型支持的
  强度档位。两者分别拥有锚点、开合、键盘、焦点恢复与响应式收敛，不使用浏览器原生
  `<select>`，也不得为了“分层”再次把强度塞到长模型列表底部。
- **权限菜单：** 以 GPT 权限批准菜单为交互参考，直接列出当前 Runtime 已支持的
  批准策略与完全访问选项，显示名称、简短后果和选中状态；选择后必须进入新建
  Session 的真实权限参数。
- **真实性：** 未接通的速度、自定义 config 或其他权限模式不进入菜单。
- **原话依据：** “参考gpt的模型切换，权限批准”。来源：当前任务与所附三张截图。

### UR-037 — Blueprint Precision 与 P5 构图语言结合，避免过素

- **状态 / 优先级：** `current / P1`
- **组合方式：** Blueprint 保留浅蓝网格、直角几何和工程秩序；P5 只提供不对称
  层叠、偏移深色底板、斜切强调条、强对比选中态与一次性弹出动效。继续使用
  PAW 蓝/墨/青配色，不复制角色、美术资产、商标或红黑主题。
- **密度边界：** 视觉冲击集中在焦点窗口、当前选择、关键菜单和状态变化，不在
  空白桌面铺满装饰，也不恢复持续滤镜动画。
- **原话依据：** “能不能我们这个风格和p5的那种ui结合，这样做有惊艳感”
  “因为实在是太素了”。来源：当前任务。

### UR-038 — 演示数据不算 Browser 或 Terminal 实现

- **状态 / 优先级：** `current / P0`
- **验收纠正：** 带“演示数据”的 Mock 页面、`preview: command accepted` 回显、
  静态 Browser 截图或 Preview transport 都不算功能完成。
- **Terminal：** 必须连接本机真实 PTY，执行用户输入的命令，回传真实 stdout/
  stderr/退出状态并响应窗口 resize。
- **Browser：** 必须启动固定 Profile 的受管 Chromium，并让可见页面与 Agent
  控制使用同一个 CDP target；Mock tab、静态演示页或第二个假页面不算完成。
- **原话依据：** “浏览器和终端都为实现”“未”（语义为“都未实现”），以及所附
  Terminal 截图中的“演示数据”和 Preview 回显。来源：当前任务。

### UR-039 — 视觉方向采用 P4 蓝色，不采用 P5 红黑主题（已由 UR-049 取代）

  保留其“避免过素、焦点层次更有冲击、禁止持续滤镜动画”的结果约束。

  不引入红黑角色主题、角色素材或持续发光。
- **原话依据：** “那就是P4的蓝色”。来源：当前任务。

### UR-040 — Agent Composer 删除快捷提示词，改为 Session / Room 单聊群聊选择

- **状态 / 优先级：** `current / P0`
- **修正关系：** 本条 `supersedes` `UR-027`、`UR-030` 中“快捷提示词进入 Agent
  Composer/设置”的要求；模型、推理强度、权限和项目仍保留。
- **交互合同：** Composer 底栏不显示“提示词”入口；原位置提供 PAW 的
  `Session / Room` 选择，分别表示单 Agent 会话与多人群聊。新建面板中不再在
  顶部重复出现第二套模式选择器。
- **用户可见验收：** 窄窗和宽窗都只出现一处 Session / Room 选择，切换后输入

  来源：当前任务。

### UR-041 — P4 蓝必须是一套配套色系，不是整页单色蓝（已由 UR-049 取代）

- **状态 / 优先级：** `superseded / P1`
- **色彩合同：** 深墨蓝负责文字与结构，钴蓝负责焦点，青蓝/靛蓝负责相邻层级与
  交互反馈，偏暖纸白负责内容面；琥珀、绿色和珊瑚红只用于提醒、成功与危险。
  不允许通过给所有背景叠同一种浅蓝来表达主题。
- **层级合同：** 桌面、Chrome、活动窗口、App 侧栏、内容面、选中项和状态必须
  具有可辨的明度与色相层级；强调色集中在焦点和状态，不把正文染色。
- **原话依据：** “这个蓝色不是纯色，而是你要用配套色系，当前非常寡淡”。
  来源：当前任务。

### UR-042 — 新建、Session 与 Room 只使用一套 Tutti 式 Composer

- **状态 / 优先级：** `current / P0`
- **统一合同：** 新建工作、已打开 Session 和 Room 都复用同一 Composer 骨架、
  输入高度、工具栏排列、聚焦态、附件区和发送位置；不能在新建页与对话页维护
  两套不同尺寸和不同控件顺序的对话框。
- **上下文差异：** 新建时显示 Session/Room、项目、权限和模型；进入具体工作后
  保留同一骨架，只把创建选项替换成该 Session/Room 的真实运行控制。差异属于
  控件内容，不属于第二种 Composer。
- **可用性：** Composer 固定在消息阅读流底部，消息区独立滚动；空对话也不能把
  Composer 挂在窗口顶部或遮挡工作台导航。
- **原话依据：** “对话页面无法使用，对话框不要两种形式，都一个对话框，你参考tutti呀”。
  来源：当前任务与所附两张截图。

### UR-043 — Agent 工作面直接采用 Tutti 的三段式结构

- **状态 / 优先级：** `current / P0`
- **结构合同：** Agent App 使用 Tutti 已验证的工作台骨架：最窄的来源/入口栏、
  可搜索且可折叠的会话栏、占据主要面积的消息内容区，以及停靠内容区底部的
  单一 Composer。不能继续用后台表格、悬空设置卡或多层空白面板拼接 Agent 页。
- **PAW 差异：** 保留 PAW 的 Session/Room、模型、权限、项目和 Runtime 数据，
  以及 P4 蓝配套色系；不复制 Tutti 的品牌、角色素材、宣传文案或黑色主题。
- **窄窗合同：** 四五个伙伴窗口并列时，来源栏先折叠，会话栏再变为可呼出的
  抽屉；消息和 Composer 始终优先，不允许保留空列或把正文压成不可用窄条。
- **原话依据：** “我们ui太丑了，哭”，以及所附 Tutti Agent 工作台截图。
  来源：当前任务。

### UR-044 — 模型/权限菜单与 Composer 不得发生任何叠压和断行破坏

- **状态 / 优先级：** `current / P0`
- **修复合同：** 模型、推理强度与权限采用锚定式分层菜单，菜单有确定的可视
  边界、碰撞翻转与关闭行为；不得使用会撑开布局或覆盖输入区的原生展开层。
- **响应式合同：** Composer 底栏在宽窗保持一行；窄窗按语义分组折叠进菜单，
  不允许权限文字逐字竖排、模型名称被拆行、Session/Room 与其他控件互相覆盖，
  也不允许弹层永久留在页面上。
- **原话依据：** “你看，全是bug”，以及所附模型弹层、Composer 和会话列表
  互相叠压的截图。来源：当前任务。

### UR-045 — 恢复旧 Agent UI 已经正常的模型分层菜单交互

- **状态 / 优先级：** `current / P0`
- **回归基线：** 旧 Agent UI 中模型按 Provider 分组、选中项清楚、列表独立滚动且
  Composer 尺寸不受浮层影响；这些已正常的交互必须保留并迁入新的 Tutti 工作台骨架。
  旧版把推理强度附在同一浮层中的布局不再作为回归基线；当前独立交互以 `UR-135` 为准。
- **禁止退化：** 不得用两个原生 `select`、悬空表单或横跨整个 Composer 的设置
  卡替代该菜单；不能为了新主题牺牲原有可用性。
- **原话依据：** “甚至之前的ui都比现在正常”“ui全是bug”，以及所附旧模型
  分层菜单截图。来源：当前任务。

### UR-046 — Agent 权限菜单必须包含全自动模式

- **状态 / 优先级：** `current / P0`
- **功能合同：** 新建 Session 与 Room 的权限菜单同时提供按风险确认、只读、
  工作区托管和全自动；全自动使用 Runtime 已有的 `full_trust` 合同并提交明确的

- **边界：** 全自动需要已选工作目录；未选择目录时菜单说明原因并禁用，选择后
  可直接创建。UI 显示“全自动”，设置页和 Composer 使用同一真实枚举。
- **原话依据：** “还有全自动模式呢”。来源：当前任务。

### UR-052 — 高级感来自媒体主视觉与有目的的运动层，不是静态换色

- **状态 / 优先级：** `current / P0`
- **媒体合同：** Overview、Agent 空白/新建态和 Room 允许使用原创图片、短视频或
  程序化媒体作为低信息密度主视觉；媒体只负责气氛与空间层次，不承载 Runtime
  真相，也不得复制明日方舟的角色、Logo、插画或宣传片素材。
- **运动合同：** 借鉴官网以媒体、遮罩、切片、位移和状态切换共同建立层次。开窗、
  抽屉、锚定菜单、模式切换和 Room 消息流只为反馈、空间连续性、状态指示或解释
  而运动；高频键盘操作保持即时，正文与可操作数据不得为了装饰持续漂移。
- **实现边界：** 界面转场优先使用 `transform`、`opacity` 与必要的 `clip-path`，
  避免改变布局尺寸造成窗口抽搐；必须提供 reduced-motion 版本。可循环的媒体背景
  必须静音、低对比且不抢输入焦点。
- **原话依据：** “他是有大量动画的，而且还有图片视频这些动画来做高级感”。
  来源：当前任务；视觉机制参考用户指定的明日方舟官网 HTML/CSS/媒体结构。

### UR-053 — 动态背景采用大众可读的名家几何抽象方向

- **状态 / 优先级：** `current / P0`
- **视觉选择：** 用户授权选择合适的著名画家方向；当前实现默认采用康定斯基式
  几何抽象语言，因为圆、弧、线、色面能拆成独立景深层并与工业信息 UI 共存。
  只借鉴公共艺术语言，不复刻任何具体画作。
- **动态合同：** 背景以原创栅格主视觉为底，前景切片、青色光带、信号线与扫描层
  通过低速 `transform/opacity` 独立运动；工作窗口和 Composer 始终静止清晰，动态
  不能引起布局重排、输入延迟或持续抢眼。
- **可访问性：** reduced-motion 下保留静态构图并取消位移、扫描与景深呼吸。
- **原话依据：** “做个有艺术感的，动态背景，找一个大众审美”“可以找一个合适的
  著名画家的风格”“动态背景”。来源：当前任务。

### UR-054 — Room 的多人形态就是主窗周围的真实卫星窗口

- **状态 / 优先级：** `current / P0`
- **窗口合同：** 进入 Room 后，主 Room 是中心窗口；最多四到五个当前活跃伙伴以
  独立、可拖动、可缩放、可最小化的 Agent 卫星窗口围绕主窗展开。卫星窗不是
  Room 内容区里的参与者卡片，也不是同一窗口内重复绘制的假窗口。
- **消息合同：** 用户需求、定向提问、伙伴答复、plan、文档、ContextRef、WorkItem
  交接和最终汇合都投影到真实源窗与目标窗之间的流动路径；主 Room 的时间线/账本
  保留可读记录。Room 内部不得再画一套重复的参与者节点来冒充卫星拓扑。
- **焦点合同：** 自动展开卫星窗后主 Room 仍保持焦点；用户明确点击某位伙伴时才把
  对应卫星窗提到前台。Overview 按同一窗口身份展示整组窗口。
- **原话依据：** “room是卫星窗口”。来源：当前任务与所附主 Room 周围伙伴小窗截图。

### UR-055 — 生图只是素材，动态背景必须由运行时运动系统实现

- **状态 / 优先级：** `current / P0`
- **真实需求：** 一张生成图片即使视觉合适也仍是静态素材，不能单独算“动态背景”。
  PAWOS 必须用独立层的平移、缩放、反向景深、裁切和扫描运动让背景持续但克制地
  变化；运动需要肉眼可辨，又不能移动工作窗口、Composer 或正文。
- **实现合同：** 固定溢出容器承载多个独立媒体层，只动画 `transform/opacity`；不得
  通过尺寸、定位重排或外框滤镜制造运动。reduced-motion 下回到同一静态构图。
- **原话依据：** “可是生图不会动动态背景”。来源：当前任务。

### UR-056 — 伙伴卫星窗只显示对话内容

- **状态 / 优先级：** `current / P0`
- **内容合同：** 伙伴卫星窗是小尺寸可读消息面，不是缩小版 Agent 工作台。除 PAWOS
  统一窗口标题栏外，内容区只显示与该伙伴有关的按时间对话；删除第二层身份栏、
  责任说明、WorkItem/上下文横条、设置、导航、常驻 Composer 和其他工具面板。
- **密度合同：** 消息字体、行高、气泡宽度和滚动区域按 280×210 起步的小窗优化，
  优先显示更多正文而不是图标、头像或装饰。发消息和治理留在主 Room。
- **原话依据：** “卫星窗口就只显示对话内容了，如果还是对话框和各种东西，就看不到内容”。
  来源：当前任务与所附伙伴小窗截图。

### UR-057 — 跨窗消息流转与到达特效必须清楚且稳定

- **状态 / 优先级：** `current / P0`
- **反馈合同：** 每次真实路由以源窗亮起、定向路径生成、带类型颜色的消息包移动、
  目标窗短促到达反馈四步表达；一对多发送按目标轻微错峰。同一事件不能无限循环，
  历史路径在短暂强调后退为低对比静态线。
- **类型合同：** 需求、问题、答复、结果和上下文/文档具有一致但可区分的颜色；效果
  只由权威消息/dispatch 触发，不用装饰动画伪造通信。拖窗和 resize 期间路径跟随
  transform 几何而不改窗口布局。
- **原话依据：** “消息流转和特效好好优化”。来源：当前任务与所附卫星窗布局截图。

### UR-058 — 挤压主内容的侧栏对象可弹成同类卫星窗

- **状态 / 优先级：** `current / P0`
- **通用合同：** 卫星窗不是 Room 私有特效，而是 PAWOS 的辅助执行窗口形态。会长期
  占据侧栏、又需要独立观察的对象可弹成卫星窗，同时保留原主对象上下文、窗口身份、
  Overview 和跨窗事件关系。
- **首个对象：** Session 的 subagent 必须能从子 Agent 列表/运行树打开独立卫星窗；
  小窗优先显示该 subagent 的公开对话、工具进度、问题/答复和最终结果，不复制整套
  启动配置、统计、设置和侧栏壳。主 Session 保持完整正文宽度。
- **原话依据：** “现在一些侧边栏也可以用这种卫星窗口”“例如session的subagent”。
  来源：当前任务。

### UR-059 — 每个 PAWOS App 都按 Agent App 的细节标准打磨

- **状态 / 优先级：** `current / P0`
- **质量合同：** Agent App 形成的基准不是单页特例。Knowledge、App Center/
  Package、Files、Browser、Terminal、Memory、Input Studio、System Monitor、
  System Settings、Project Workbench 和 Room 等每个 App 都必须逐一收敛到同一
  级别的排版、响应式窗口行为、滚动、菜单锚定、状态反馈、动效与 reduced-motion
  质量；不能用统一换色或卡片套壳代替细节迁移。
- **验收合同：** 每个 App 至少有一个可操作的真实纵向切片，窄窗口不裁切核心内容，
  主要动作有明确结果或恢复路径，装饰动效不妨碍输入与正文阅读。未完成的 App
  继续保持可切换的旧前端回退，不得用静态 Preview 冒充完成。
- **原话依据：** “后面每一个app，例如知识库，插件，app这些等都得像agentapp一样
  仔细打磨”。来源：当前任务。

### UR-060 — Composition 8 静止层优先原画，矢量只作稀疏特效

- **状态 / 优先级：** `current / P1`
- **静止合同：** Composition 8 使用唯一的原画 master 作为静止底图；暂停或
  reduced-motion 时必须基本保持原画截图的构图、肌理和层次。
- **矢量合同：** 只保留轨道、环、线束、弧线、网格和音乐虚线等少量 outline-only
  特效；不得再次绘制已经存在于背景中的大色块、棋盘、三角和圆面。矢量分组
  应有清晰命名，供其他 PAWOS App 选择性复用，不复制整张图。
- **Image 2 扣除合同：** 以原图生图得到的 `kandinsky-composition-viii-base-image2.png`
  只负责扣除将由 SVG 负责的细线/重复轮廓，原图和较早 Image 2 版本必须保留作回退对照。
- **默认渲染合同：** `PawCompositionField` 默认 `effects=false`，静止桌面只渲染完整
  Image 2 底图并以 `slice` 覆盖任意缩放后的 viewport；只有完整物件组才能显式启用
  SVG，禁止把同一物件拆成半原图、半矢量的叠加。
- **原话依据：** “静止的时候要基本截图下来和原画一样”“背景图重复的部分扣掉”
  以及“矢量多就容易乱”。来源：当前任务及附件
  `composition_8_music_reactive.html`、`kandinsky_music_motion.html`。

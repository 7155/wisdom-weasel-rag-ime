### UR-183 — PAWOS 桌面用可拖动 App、项目文件夹与对话文件图标管理工作

- **状态 / 优先级：** `current / P0 desktop surface`
- **真实需求：** 桌面本身是完整图标画布。App、项目文件夹、Session/Room 对话
  文件都以真实桌面图标呈现，可在桌面拖动并持久化位置；项目文件夹点击展开，
  对话图标可拖入项目归类，也可拖入归档区并恢复。
- **投影边界：** 这些文件夹和对话文件是 PAWOS 为用户直观看到对话、状态与
  进度而提供的 OS 投影，不要求创建 Finder/Git 中可见的真实文件。归档只改变
  PAWOS 桌面组织，不删除 canonical Session/Room。
- **视觉验收：** 名称默认至少显示两行或多行，不能只显示不知所云的单行截断；
  hover/title 可查看完整名称；风格可按 PAWOS 主题变化，不固定为 macOS 蓝色文件夹。
- **原话依据：** “文件夹只是os的显示而已，分别用户直观看到对话和状态进度”；
  “桌面是真的图标，可以拖动那种，还能归档这些”；“是这种文件夹”；“风格不一
  定要蓝色这种”；“为什么不是全屏可以拖动，而且名字都显示不全”；“文件夹和app”。
  来源：当前任务，2026-08-28。

### UR-184 — 协同模式在可用桌面内自动铺开所有运行中行星并保持清晰布局

- **状态 / 优先级：** `current / P0 Room collaboration UI`
- **真实需求：** 进入协同模式后，Room 主窗在中间缩小，当前 Room 名册中所有
  active 行星观察窗自动弹出并环绕 Room；行星可在任务中动态新增、删除，界面
  同步增删对应窗口。使用顶栏下方的整个可用桌面，不保留大面积无意义边距。
- **布局要求：** 同一名册与视口得到稳定位置；窗口不重叠、不越界，窄屏可降级
  为可滚动 rail。协作图采用清晰的有向分层表达，聚合重复边，边和标签不穿过
  节点；失败/冲突摘要放在图外，不把节点区挤乱。
- 运行中的行星必须由真实 Runtime active 状态驱动轻量流光/状态动效；已完成、失败、未开始或
  detached 的行星不得伪装成运行中。遵守 `prefers-reduced-motion` 时改用静态状态点或一次性变化，
  不得靠前端计时器制造假运行。
- 动态名册验收覆盖同一任务从 2 个行星扩展到 8 个行星，以及中途删除、重新添加或替换行星；任务表和
  协同窗口按稳定 `roomTurnId`/Session ID 同步增删，不重复、不丢失，重新编排后仍不重叠、不越界。
- **原话依据：** “协同模式才是中间缩在，卫星窗口弹出铺满桌面”；“协同模式
  没有弹出所有行星，并且位置很乱”；“这个也乱”；“尽量铺满呀”；“这个也是没
  铺满”。其中本条按后续术语修正：这里自动弹出的是行星，卫星仅指 subagent。
  来源：当前任务，2026-08-28。

### UR-185 — Session 消息、思考、工具与 steer 严格按权威追加时间线呈现

- **状态 / 优先级：** `current / P0 transcript correctness`
- **真实需求：** 前端按 Runtime/JSONL 的实际追加顺序呈现每个用户消息、steer、
  思考、工具开始/结束和最终回复。用户在执行中插入的消息出现在插入时刻；同一
  回合最终回复必须位于它前面的思考与工具之后，且只显示一次。刷新、durable/
  live 合并、增量更新都不得丢旧消息、侧边跳转点或已经可见的思考。
- **原话依据：** “什么时候插入就把这个消息放到什么时候，就按照时间线 就只
  按照时间线”；“怎么可能输出结果结束了还输出思维”；“前端存在消息丢失，我
  之前发的消息全部看不到。而前面他的思考 全部消失了”；“前端现在只能看到一个
  消息。侧边的消息跳转条也没有了”。来源：当前任务，2026-08-28。

### UR-186 — Trace Agent 始终提供明确诊断动作并绑定完整 Room 运行证据

- **状态 / 优先级：** `current / P0 Trace Agent App`
- **真实需求：** Trace Agent 可选择任意 Session、Room 或运行记录。选择 Room
  后，主诊断动作始终可见，不会因列表过长滚出视口；一次诊断关联主持 Session、
  全部行星及其 subagent、WorkItem、工具失败、上下文装配、Trace、记忆/RAG 证据，
  分析失败原因、任务分配、反复打回与 token 浪费，并给出报告和可授权修复建议。
- 诊断输入列表必须使用服务端真实游标分页或搜索；“任意历史对象”不能被固定 200/500 条上限截断。
  加载更多时按游标继续读取并按 canonical ID 去重，保留跨页的 Room/Session/run 关联；分页失败须显示
  可操作的真实原因。
- **原话依据：** “选择当前我这个 Room 的对话记录……让他去排查”；“工具调用
  哪些失败，上下文有哪些问题，还有任务分配有哪些问题”；“这个流程有哪些是
  冗余的？分配不合理，导致浪费token，反复打回这种情况”；“记得做traceapp的
  时候，给那个agent配套技能”。来源：当前任务，2026-08-28。

### UR-187 — Room 任务与结果内容正确渲染 Markdown 和可打开文件引用

- **状态 / 优先级：** `current / P0 Room content rendering`
- **真实需求：** 行星任务表、公开进展、结果与证据保留 Markdown 的段落、列表、
  粗体和代码语义，不把 `**`、反引号等 token 当作普通文字展示。结果中识别出的
  工作区文件可直接跳转到 Files/对应文件；长表自身可滚动，展开结果时不把底部
  留成无意义空白。
- **原话依据：** “md没有渲染”；“结果明明是文件却无法跳转”；“这些文档我全部
  点不了”；“行星表格无法滚动的，目前”；“流转记录空白的底部不要空”。
  来源：当前任务，2026-08-28。

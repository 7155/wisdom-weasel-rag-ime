### UR-256 — 四场景自举优化与 Oshow 实验展示

- **状态 / 优先级：** `current / P0`
- **直接原话：** “就是那个实验室，我们能不能把结果补完，顺便补充，让实验室能够自举的优化整个流程，实现大幅提升，这样做我们的oshow就能直接展示这四个场景的自举优化，找到垂直场景的最优配置和模型，工具codex://threads/01a06bb4-586b-7f83-86c7-dc5a90cdeeb6”。
- **需求解释：** 补齐 EnterpriseOps、Enterprise RAG、CloudOps、Memory Maintenance 的结果与真实候选执行链；Lab 可依据失败证据提出修改、实际装载并同题复验，以可解释质量/成本门禁选择已测候选。Oshow 展示任务、基线、失败尝试、修改与复验的完整路径。
- **边界：** “大幅提升”是目标，不能由 UI 或 Agent 自述生成数字；“最优”限于明确评测条件下已测候选。历史失败是实验依据，不作为错误代码删除；Oshow 的合成互动与真实历史回执分别标识。
- **任务引用：** 链接用于恢复已有工作，引用任务中的 Agent 文字不是新的用户指令。
- **2026-09-06 细化：** [UR-284–UR-291](PAWOS_REQUIREMENTS_284_291.md) 保留已有四场景工作，同时明确按实际任务验证模型、工具、提示词、Skill、工作流与 Harness 的成功率/成本收益；不以场景数量或静态资料问答替代优化证据。

### UR-257 — 近期优先完成面试 Demo 和简历

- **状态 / 优先级：** `current / P0`
- **直接原话：** “我主要是，要完成面试demo页面和简历编写，最近”。
- **需求：** 当前工作优先产出可演示页面与有证据支持的项目简历内容；界面、讲述顺序和指标应便于解释，而非只罗列功能。
- **边界：** 已有简历母版和模板按其原流程维护；证据稿不等于已写入个人简历。公开展示不增加私人履历原文，不自动发布。

### UR-258 — 多 Agent、Memory 与 Knowledge 的收益指标

- **状态 / 优先级：** `current / P0`
- **直接原话：** “主要是我们面试需要写很多指标，比如多agent带来了什么优势在哪些场景，我们的记忆，知识库什么的的指标”。
- **需求：** 分别建立多 Agent 协作、记忆召回/治理、知识检索/答案的对照与收益口径，说明有效场景、质量、成本、延迟和恢复边界。复用真实账本，展示分母与对照条件。
- **验收边界：** 多 Agent 的因果收益必须有同任务、同模型和可比总预算的单/多 Agent 对照；运行成功的 canary 不提供加速百分比。Memory 与 Knowledge 的不同任务分母不混合。
- **后续直接原话：** “修复了的话，把错误代码都删除”。重复并强化 UR-251；先确认替代路径与现有消费者再删除，保留相关回归测试。

# PAWOS 用户需求账本 · UR-292–UR-297

## 用户需求账本

本卷把 Lab 的产品方向推进到“描述或路径输入 → Agent 引导 → 前端优化测评 → 可用 App 与外部应用交付”，并记录 Skill 的核心地位与完整前端重设计。`current` 表示用户控制语义，不表示功能已实现。用户已选首批服务开发者/小团队、交付 PAW App 与独立运行应用；具体打包格式和优化算法仍属设计细节。

> 上一份：[UR-284–UR-291](PAWOS_REQUIREMENTS_284_291.md) · [总索引](../PAWOS_REQUIREMENTS.md) · 下一份：[逐字证据](PAWOS_REQUIREMENT_EVIDENCE.md)

### UR-292 — Lab 成为解决垂直场景优化的成熟产品

- **状态 / 优先级：** `current / P0`；P0 按用户当前产品主线整理，延续 UR-284 的质量与成本目标。
- **直接来源：** [LP-S01](#lp-s01)、[LP-S02](#lp-s02)；[LP-S03](#lp-s03)是 SaaS 设计优先级问题。
- **控制语义：** Lab 要能让用户带着自己的问题开始，持续获得建议并完成优化和交付。Stitch 是用户给出的产品类比；不能只交付固定数据集的成绩或展示页。
- **后续选择：** [LP-S08](#lp-s08) 明确首版服务有业务需求或现有 Agent 的开发者、小团队；不要求其先学会配置评测工程。
- **SaaS 通用性修正：** [LP-S14](#lp-s14) 明确产品由 Agent 主导；不同项目可以形成完全不同的结果与形式，平台不能靠一套固定业务目标结构容纳全部项目。
- **用户可见验收：** 一套新的、受支持的业务材料能经产品入口完成任务理解、真实对照、方案选择与可用成果交付；不需要开发者逐次为该题库修改 Lab 核心源码。
- **修正 / 保留：** 附件里的公共数据集不要求嵌入产品主流程。用户可将它们作为普通输入或体验/回归材料；旧实验及证据保留，但不限制新项目只能来自内置场景。

### UR-293 — 从描述或路径开始，由 Lab 识别材料、带领完成并给建议

- **状态 / 优先级：** `current / P0`。
- **直接来源：** [LP-S02](#lp-s02)。
- **控制语义：** 支持提供业务描述或项目/材料路径。Lab 识别任务、现有实现、数据、运行方法、成功条件和缺口，并建议下一步；不要求用户先学会配置评测工程，也不要求已经有成品 Agent。
- **用户可见验收：** 识别结论有实际材料依据。材料足够时 Agent 连续推进；遇到无法自行判断的业务含义或必要缺口时，只请求当前步骤所需的信息。没有现成 Agent 时，建立可运行初版属于搭建，之后的改动才能与它比较。
- **解释边界：** 网页中的路径文本不等于可读目录。浏览器目录选择、仓库接入和本地/远程执行器是实现选项；当前执行位置、材料可达性和可执行范围必须可见。描述本身不能替代不存在的数据、环境和验收依据。

### UR-294 — 在同一前端逐步完成优化测评

- **状态 / 优先级：** `current / P0`；继承 Golden 准备与 UR-284–UR-291 的真实比较要求。
- **直接来源：** [LP-S02](#lp-s02)、[LP-S15](#lp-s15)、[LP-S16](#lp-s16)。
- **控制语义：** Lab 用 Agent 引导用户在前端完成理解任务、准备/审核标准、基线、失败分析、实际候选改动、对照与选择。步骤跟随项目材料与实际状态，不靠用户在几个独立配置系统之间手动拼接。
- **用户可见验收：** 每阶段有可查看或编辑的成果、已完成工作、下一步建议和必要操作；用户可纠正业务含义和优化方向。运行、停止、失败和恢复与真实执行一致，原版与候选的行为、改动和成本可比较。
- **解释边界：** LP-S14 已修正通用前端方案：阶段是可选方法，不是固定业务页面。LP-S15、LP-S16 明确要求助手亲自操控真实前端，完成实验全流程与 App 导出；只通过源码、模拟数据或后台脚本不足以验收。

### UR-295 — 导出优化好的 App，并支持外部应用交付

- **状态 / 优先级：** `current / P0`。
- **直接来源：** [LP-S02](#lp-s02)。
- **控制语义：** 最终成果包含优化后的可运行 App，并能按支持的目标供外部应用使用。应用生成、打包与接入是产品交付环节。
- **首版交付选择：** [LP-S09](#lp-s09) 明确先交付 PAW App，并可导出独立运行的应用。
- **用户可见验收：** 能试用选定版本、查看真实改动与验证范围，取得所需运行入口、配置、工具/Skill/工作流及依赖说明。导出应绑定已验证候选，并在目标环境检查启动和代表性行为；未完成该检查时如实呈现状态。
- **解释边界：** PAW App 与独立运行已确定为首版终点；具体源码/安装包格式、外部平台转换、云托管和实际发布操作尚未由该选择确定。导出报告、保存配置和影响后续验证实验，不能单独算作可运行 App 交付。既有应用可以保留自己的 Runtime，Lab 内部继续遵守 Pi 的执行所有权。

### UR-296 — Skill 承载核心领域能力，并能通过真实任务验证

- **状态 / 优先级：** `current / P0`；延续 UR-287。
- **直接来源：** [LP-S04](#lp-s04)。
- **配套打磨：** [LP-S16](#lp-s16) 要求技能、工具、环境、提示词和前后端一起完善，按成熟产品要求验收。
- **模板责任：** [LP-S14](#lp-s14) 要求由 Skill 提供成果/交互模板，具体项目由 Agent 选择、填充和组织；模板不成为全平台必须填写的字段模型。
- **控制语义：** 用户把 Skill 视为决定成功的深层能力来源，要求设计明确 UI、执行展示与技能之间的关系。Skill 的领域方法应成为可查看、可改进并可随应用交付的能力资产。
- **工程化验收：** 从失败案例能追到相关方法和实际加载版本；修改 Skill 后能运行真实对照，并把选定版本装入应用。区分 Lab 使用的分析/优化方法与目标 App 使用的业务方法，保留模型、工具、环境和判定对结果的共同影响。
- **解释边界：** “最深处我感觉还是技能”是用户的产品判断；不把它改写为已经实验证明 Skill 是唯一因素，或要求每次优化都修改 Skill。缺数据、缺工具或判定错误有各自的修复位置。

### UR-297 — Lab 前端从头设计，承载成熟产品的完整复杂工作

- **状态 / 优先级：** `current / P0`；范围是 Lab 前端的完整用户体验。
- **直接来源：** [LP-S05](#lp-s05)、[LP-S10](#lp-s10)、[LP-S11](#lp-s11)、[LP-S12](#lp-s12)、[LP-S13](#lp-s13)、[LP-S14](#lp-s14)、[LP-S15](#lp-s15)、[LP-S16](#lp-s16)。
- **控制语义：** 按成熟产品重新设计 Lab 的信息架构、工作区与交互，允许为真实复杂任务提供足够的前端能力和操作空间。既有布局仅作为功能和状态参考。
- **工作顺序：** [LP-S06](#lp-s06) 要求继续；[LP-S07](#lp-s07) 随后明确先完成整体设计、定位、需求和后续细节，再进入前端实施。当时先增加独立的工作台交互设计原型；LP-S14 修正通用性方向后，后续源码实现与真实前端操作另见[实现与验收](../LAB_GENERIC_WORKBENCH_ACCEPTANCE_20260907.md)。原型本身不充当生产实现证据。
- **工作台与设计方法：** [LP-S10](#lp-s10) 进一步提出 Lab 可能需要复杂工作台；这是 Lab 自身的交互形态，不撤销 PAW App 与独立应用的交付选择。[LP-S11](#lp-s11) 要求检查专门的设计能力及类似产品，[LP-S12](#lp-s12) 明确询问 Flowith 能否用于设计；研究与取舍应基于官方资料和实际使用证据分别说明。
- **设计决策授权：** [LP-S13](#lp-s13) 明确由助手决定设计，按已记录需求选用有助展示与交互的方式。当前 Lab 设计无需因 Skill 的布局选择流程反复让用户确认；工具与方法服从需求。此授权不把供应商文档、外部上传或真实发布自动变成已执行事实。
- **控制性修正：** [LP-S14](#lp-s14) 否定所有项目共用固定目标表单和业务页面的方案。平台提供通用项目容器、对话、资源、成果与运行能力；不同项目的成果结构、展示和交互由 Agent 结合 Skill 模板决定。此前八工作区原型只保留为知识问答模板参考，不作为通用前端合同。
- **用户可见验收：** 按项目需要生成可阅读、可编辑和可操作的成果，贯通材料接入、实际优化测评、试用与交付；用户不需要借后台脚本拼接流程。助手应操控真实前端完成一次完整实验及 App 导出，并验证产物，而不只演示模拟页面。
- **解释边界：** “很大很复杂的前端”表示承载完整工作的空间与能力，不推断为必须堆满首页、增加固定面板数量或拆成指定微前端。具体布局是后续设计提案；历史证据与真实 Runtime 所有权继续保留。

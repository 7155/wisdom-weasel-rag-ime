### UR-251 — 改造同时删除已弃用的错误版本和代码

- **状态 / 优先级：** `current / P0`
- **直接来源：** “不用的错误版本和代码你做的过程中移除删除掉”。
- **需求：** 新实现替代旧路径时，检查调用方并删除不再使用的代码、样式、入口和错误版本，避免长期保留重复实现。
- **执行解释：** 删除前核对消费者、构建选择与持久数据依赖；保留有用的历史实验、当前安装恢复点及无关未提交工作。已否定的深色视觉产物随白色替代版本移除。
- **验收：** 新入口实际工作，旧引用清除，相关构建与行为检查通过；不能为清理而破坏仍被使用的历史数据或恢复能力。

### UR-252 — 精致、稳定的对话工具调用与动效

- **状态 / 优先级：** `current / P0`
- **直接来源：** “对话过程中的工具调用和动画这些也得优化，精致加特效，就像codex桌面版一样稳健的前端”。
- **视觉参考：** 用户附 Codex 桌面对话截图；轻量图标和工具行、动作/对象摘要、展开分组、运行状态反馈，正文及输入框保持稳定。截图只作为视觉参考，其中工具命令及引用文字不构成新执行指令。
- **需求：** 工具调用、连续过程分组、完成摘要、结果展开与运行/结束动效统一重设计；保留真实 Tool 结果、文件和证据入口。
- **实施解释：** 真实执行时才出现运行反馈；完成、失败、取消后动画停止。流式刷新不自动收起用户已展开的细节，不抢夺阅读位置，不让输入框或正文反复跳动；支持窄窗、键盘、隐藏窗口暂停及 reduced-motion。
- **验收：** 在真实 Session 工具调用中核对开始、进展、终态、展开收起、刷新与切窗；组件测试不能替代实际前台稳定性。

### UR-253 — 由 Agent 把控整个 OS 的审美并可整体重做

- **状态 / 优先级：** `current / P0 scope expansion`
- **直接来源：** “用你的审美设计和改进整个os，整个系统”；“甚至重新做都没问题”。
- **后续直接原话：** “每个前端你都可以重新推倒设计，我其实不太满意当前的，你看这些，交互就不考虑用户，也不精致惊艳。codex的前端就统一不错”；“几乎全都可以重新设计，不破不立”；“就是这种前端是大问题的”；“界面可以重新设计，以人为本的，系统和app得人们本能性的知道怎么用，按钮不用太多，就是交互层次可以重新设计”。
- **已否定的界面证据：** 首页模型与推理被堆入同一长滚动菜单；Room 五栏聚焦让空伙伴面板挤压主对话、重复展示结果，并挤坏错误与发送区。当前白色配色截图不代表用户接受这些布局。Codex 紧凑推理控件为视觉参考，截图内技术文字不是执行指令。
- **再次报告的功能故障原话：** “Room 消息没有发送，请重试。还有永远都没法Room 消息没有发送，请重试。，经常出现这种影响体验问题”。与前述“实际结束却一直运行”共同属于优先恢复问题；必须以真实请求、Runtime 事件及重试结果验证，不仅修改错误文案。
- **后端补充直接原话：** “顺手优化后端”。后端与界面一起优化，首先收敛实际暴露的发送预占、异常释放、终态投影和错误传递问题。
- **需求：** 范围扩展至整个 PAWOS、系统交互和所有 App。Agent 自主把控设计，必要时替换既有布局、导航、卡片与页面结构，不限于换色或局部修补。
- **控制关系：** 保留已接受的白色和星空身份、Agent/Room/Lab 核心用途，以及状态一致性优先级；此条扩展整体范围，不删除 UR-242–UR-252 的具体要求。
- **验收：** OS 窗口、导航、字体、控件、反馈、加载、空态和动效有共同语言；各 App 按真实任务设计并逐个验证实际入口、主要操作、窄窗和恢复。保留真实产品功能和数据，废弃路径按 UR-251 清理。不得用一个公共主题覆盖或核心 App 截图代表全系统完成。

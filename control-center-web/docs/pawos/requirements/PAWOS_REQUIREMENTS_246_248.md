### UR-246 — 体验优先并以 Astra 并行完成

- **状态 / 优先级：** `current / P0`
- **直接来源：** “并行完成吧，第一是体验，安全这些还有哈希这些不重要”；“你subagent也用astra”。
- **需求：** 对独立的状态恢复、Room 权限、结果展示等任务并行推进，子 Agent 使用 Astra。可见完成、流畅交互和真实运行优先；哈希、可选来源和审计不得成为正常运行的前台门槛。
- **实施解释：** 不为可逆本地修复反复询问许可，不增加第二轮审批；保留数据与准确执行对象的基本边界，在后台完成必要检查。

### UR-247 — Room 创建时配置分层权限并默认全权限免重复批准

- **状态 / 优先级：** `current / P0`
- **直接来源：** “还有room模式下，要不然就新建对话可以选择设置各个层次的权限，要不然默认就全部全权限无需批准，不然就没法运行”。
- **需求：** 新建 Room 时清楚呈现各层权限，或默认所有执行层为全权限。不能因为伙伴继承错误、隐式受限或反复批准而无法运行。
- **采用方案：** 新建对话可设置 Room、Partner、Tool Agent 各层；默认全权限并继承给实际执行。用户明确选定受限权限时保留该选择。一次创建授权贯穿当前 Room 派发，不增加逐 Tool 二次批准。
- **验收：** 创建请求、持久策略、派发给 Pi 的配置一致；默认 Room 可直接启动和运行伙伴工具；显式限制可用且不被默认覆盖。

### UR-248 — 表格保留为过程视图，重做 Room 结果阅读体验

- **状态 / 优先级：** `current / P0`
- **直接来源：** “甚至这个ui都可以优化，目前表格是可以，但是看结果是不好看的”。
- **需求：** 可以保留任务表格，但最终结果必须是好读、好看、可行动的主内容。主持汇报、真实最终结果、伙伴产物和完整过程各有层次，避免长段结果挤在表格或装饰性卡片中。
- **验收：** 主结果正文完整，产物可以打开；过程/伙伴证据可展开，窄窗和键盘操作可用；状态与结果事实一致，不从口播猜测完成。

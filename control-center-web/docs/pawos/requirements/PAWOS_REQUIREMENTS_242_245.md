### UR-242 — 面试项目围绕 Agent 工作台和垂直场景优化测评

- **状态 / 优先级：** `current / P0 product focus`
- **需求：** 优化系统 UI 与交互，重点打磨 Agent 聊天（可接入记忆、RAG、真实且有视觉表现力的多 Agent）和垂直场景优化测评两个核心 App。其他能力仍保留，按需从次级入口到达。
- **已接受解释：** 面试以评测驱动质量/成本改善为主线，Agent 的上下文和协作为支撑，产品能力由实际体验证明。保留桌面，突出两个核心 App，并使运行、诊断、实验与应用版本的证据链可往返。
- **直接来源：** “目前是作为面试项目，主要是一个agent 聊天（可以接入记忆，rag和酷炫对的多agent），另一个就是对各种垂直场景进行优化测评”；“所以，1先优化系统ui和交互。2优化主要是一个agent 聊天（可以接入记忆，rag和酷炫对的多agent），另一个就是对各种垂直场景进行优化测评这两个app，，grill me，我们看看如何优化”；“全部推荐，traceagnet有两个功能，所以trace 需要设计两个app吗”。

### UR-243 — Agent 单次诊断与 Lab 批量实验共用 Trace 并重新设计前端

- **状态 / 优先级：** `current / P0 interaction architecture`
- **需求：** 明确单次运行诊断修复和垂直场景批量测评优化。复用 Pi Session/Room 的执行、停止、恢复与通信能力；交互流程、信息架构、前端工作面重新设计。
- **已接受交互：** Agent 保持稳定主对话，真实委派后展开协作区；多窗口协作由用户主动展开。单轮诊断按结论、原因和证据、修改、复验组织，必要时转入 Lab。Lab 以实验工作区为中心，Agent 对话用于解释与干预；共享 Trace 详情可以独立开窗，不因两项功能机械增加两个 Trace App。
- **Room 补充原话：** “room的展示感觉也需要重新设计和优化”；随后选择“直接实现并展示真实 Room（推荐）”。保留行星伙伴视觉，重新组织主窗口的目标、协作过程和最终结果；不是只调整伙伴小窗。
- **验收：** 原对话、Case、实验、版本、Trace 和返回来源可追踪；关闭面板/窗口不改变 Runtime 工作。聊天、加载、恢复、窄窗及 reduced-motion 均可操作。
- **直接来源：** “两个app的流程如何设计。是上面的‘单次运行诊断修复’和‘垂直场景批量测评优化’”；“交互和体验我们得重新设计，可以复用agent的session和room，但是交互和前端得重新设计。支持两层。Enterprise RAG”；随后对 Q8 实验为中心、Q9 稳定主对话与可展开协作建议回复“好”。

### UR-244 — Lab 有界自主优化支持两层并以 Enterprise RAG 打通

- **状态 / 优先级：** `current / P0 evaluation workflow`
- **需求：** 用户设定目标、修改范围、预算与停止条件后，Agent 连续提出候选、执行、比较和淘汰，用户可查看、干预与停止；支持配置层及实现层优化，首个完整场景为 Enterprise RAG。
- **已接受流程：** 设置实验、运行、检查结果、应用版本。任务与数据、基线、实验、对比、版本各有清晰入口；展示逐 Case 结果、实际 diff、质量/成功率、Token、成本与观察性耗时。无有效改善也是正常终态。保留候选与应用到指定场景分别表达，已有 Session 保持稳定资源快照。
- **真实性：** 自主运行必须来自实际 Session/Room，不能把历史矩阵或对话口播当优化执行器；实现层候选在隔离候选环境验证。单 Case 修复不自动等于批量质量改善。
- **直接来源：** 对 Q5 有边界自主优化推荐回复“推荐后者”；对 Q6 两层优化和 Q7 主场景回复“交互和体验我们得重新设计，可以复用agent的session和room，但是交互和前端得重新设计。支持两层。Enterprise RAG”。

### UR-245 — 先统一 OS/后端/Pi 终态，再优化 Agent，最后完成 Lab

- **状态 / 优先级：** `current / P0 execution order and consistency`
- **需求：** 首先保证 PAWOS、PAW 后端和 Pi 对同一 Session/Room/turn 的运行与终态一致，修复反复出现的前后端问题；随后按已有需求与设计完成 Agent App 加载、动画和界面优化；这些完成后再完成 Lab App。
- **具体症状：** 用户确认“**一直显示运行中，实际已结束**”。首先沿真实 Runtime terminal、持久事件、HTTP snapshot、SSE/recovery、共享 projection 和 UI consumer 定位最早分歧。
- **验收：** 已完成/失败/取消的真实回合在 Agent、Room、伙伴/子 Agent 窗口和桌面状态正确收敛；刷新、重连、切窗不复活旧 running。不能用前端计时器猜成功或仅隐藏 spinner。加载保留已确认消息；输入、Stop、折叠与流式滚动稳定。源码、测试、构建、安装、Runtime 与前台证据分别记录。
- **执行边界：** 本顺序修正旧工作文档中 Lab 优先的顺序。当前请求不自动授权提交、推送或覆盖无关 dirty work。
- **直接来源：** “所以第一步，你得把我们os和pi的前后段状态完全一致，当前前后段反复出bug，然后agentapp的加载和动画，界面优化，这些有设计和需求文档的。这些完成就完成lab app”；异步症状问答回复“一直显示运行中，实际已结束”。

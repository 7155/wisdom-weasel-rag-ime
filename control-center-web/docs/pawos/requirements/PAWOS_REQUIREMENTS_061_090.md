### UR-061 — PAWOS 默认采用第三个直角主题

- **状态 / 优先级：** `current / P1`
- **默认外观合同：** 三个主题中第三个“蓝图系统”作为 PAWOS 新安装/无偏好时的
  默认主题；窗口、按钮、面板和 App 卡片默认使用直角几何，不以圆角玻璃作为
  维护基线。其他主题仍可在系统设置中主动切换。
- **原话依据：** “默认维护的风格是第三个就是那个都是直角的那个”“就是那三个
  主题直角的那个”。来源：当前任务。

### UR-062 — App 窗口顶栏为内容让位，红黄绿优先

- **状态 / 优先级：** `current / P1`
- **窗口合同：** App 内容占满窗口工作区，不再保留占面积的白色顶栏背景；窗口
  控件保持可见但以透明/浮层方式覆盖内容。红、黄、绿交通灯先占左侧固定槽位，
  标题从其右侧开始排版，不得与交通灯重叠。
- **窄窗/拉伸合同：** 窗口拖动、缩放期间隐藏可省略的标题和辅助文字；恢复稳定
  尺寸后再显示。标题不得挤压正文，也不得制造横向溢出。
- **原话依据：** “app就不要上面的白框了，占面积”“像这样做，把顶部的字为红黄绿
  让位”“窗口拉伸过程中，字该隐藏得隐藏”。来源：当前任务及附件。

### UR-063 — Agent 对话排版收敛为紧凑阅读尺度

- **状态 / 优先级：** `current / P1`
- **排版合同：** Agent 聊天正文、标题、元数据和工具信息按 PAWOS 窗口尺度使用
  紧凑字号；窄窗中辅助标签可隐藏，正文必须可读且不被截断。该合同只收敛 PAWOS
  新前端的呈现，不改变 Agent 数据、Session/Room 权威或消息语义。
- **原话依据：** “当前字体大了”“聊天字体大了，其他你也看着改”。来源：当前任务。

### UR-064 — 各 App 适配统一新前端，按功能接通而非复制工作流

- **状态 / 优先级：** `current / P0`
- **产品合同：** 输入法、知识库、记忆、规划、项目工作台、App Center、系统监控、
  设置、Files、Browser、Terminal 等均适配 PAWOS 新前端的排版、窗口、状态反馈和
  缩放规则；不要求每个 App 都复制 Agent 的独立纵向工作流。每个 App 保留自己的
  领域入口和现有真实能力，逐项接通到正确 Runtime/transport，空数据、加载、失败
  和恢复路径必须明确。
- **结果窗口合同：** Agent 可按受控 renderer 生成独立结果窗口，覆盖 HTML/网页、
  游戏、音乐可视化、图片、音频和文件产物等形式；窗口使用统一 PAWOS chrome，内容
  使用既有隔离/回执边界，不引入第二个 Runtime，不把任意外部页面当作可信内嵌。
- **推进顺序：** 先完成窗口/主题/缩放基础层，再逐 App 适配视觉与状态反馈，随后
  接通结果窗口与 renderer，最后做跨 App、Room 卫星窗和前台验收；本条作为后续
  实现排序依据，聊天即时反馈不改变该顺序。
- **原话依据：** “重点是本项目的app。输入法，知识库，记忆，规划，等等等等”“不是
  都要有自己的纵向工作流，而是适配新的前端，漂亮精致，而且功能都要逐个接通了”。
  来源：当前任务。

### UR-065 — 所有 App 子页面必须遵守同一套 PAWOS 窗口基线

- **状态 / 优先级：** `current / P0`
- **页面合同：** App 的二级页面、详情页、设置页、列表页和错误/恢复页不能继续
  使用旧前端的白色顶栏、过大的间距、独立圆角卡片或未适配的字体层级。它们必须
  继承 PAWOS 的透明标题栏、红黄绿固定槽、直角 Blueprint 几何、窄窗收缩、滚动、
  键盘焦点和 reduced-motion 规则，同时保留页面自己的真实领域动作。
- **验收合同：** 以每个 App 的入口页和至少一个子页面分别检查宽窗、窄窗、加载、
  空、成功、失败和恢复；不得只验 Agent 主入口就宣称全局完成。
- **原话依据：** “每个 app 都得注意”“很多子页面没有改正”。来源：当前任务。

### UR-066 — Session 首次发送必须复用 Tutti 式即时加载链路

- **状态 / 优先级：** `current / P0`
- **交互合同：** 从 Agent 新建入口发送第一条消息时，直接采用 Tutti 已验证的
  对话加载顺序：先建立唯一 Session identity 和消息占位，再立即切入 Session
  窗口，随后流式填充运行状态；不得先等待 Provider 完成才打开窗口。点击 App、
  新建 Session、发送、Steer 和 Stop 的可见反馈必须由本地 desktop/Session 投影
  立即产生；Pi 模型目录、权限目录、完整历史快照和 Provider 回执只能在后台补齐，
  不能成为开窗或首条用户消息可见的前置条件。
- **状态合同：** 创建中、运行中、失败、重试和迟到事件必须由同一
  Session/desktop authority 去重；发送按钮进入 pending 后锁定重复提交，保留
  Stop/Retry 语义。Provider 延迟或失败不能制造幽灵窗口或幽灵回复，失败必须在
  当前 Session 窗口给出可重试恢复。
- **验收合同：** 测试必须按顺序观察首条消息、Session target identity、runtime
  runId、窗口打开和最终状态，并覆盖延迟、失败、重试与迟到事件；同时记录点击到
  窗口可见、发送到用户消息可见、Steer/Stop 到状态变化三段交互延迟。
- **原话依据：** “大问题，很多子页面没有改正，并且发一个消息等好几秒才能进入
  session 界面，然后又失败，然后突然又弹出”“直接照搬tutti的对话加载，因为那个
  无任何延迟”“对接pi这些，窗口tutti，他没什么延迟，交互很快，瞬间就能看到和反应”。
  来源：当前任务及附件截图。

### UR-067 — 文件与子 Agent 使用独立可操作窗口，任务中心只保留必要信息

- **状态 / 优先级：** `current / P0`
- **窗口合同：** Files 必须继续使用真实工作区目录、文件读取和预览能力；子 Agent
  从当前 Session 的运行列表打开独立卫星窗口，显示该子 Agent 的公开对话、工具
  进度、问题/答复和结果，不把完整 Session 侧栏复制进小窗。窗口仍由同一个 PAWOS
  desktop authority 管理身份、焦点、bounds、最小化和恢复。
- **任务中心合同：** 任务中心仅显示当前回合必要的状态、最近关键步骤、待处理动作
  和恢复入口；详细文件、子 Agent、结果和完整历史通过对应窗口打开，不再把所有
  信息堆入一张满屏侧栏或消息流。
- **原话依据：** “这些文件呀，这些都有功能了。然后子agent可以弹出”“就留任务中心
  显示一些必要信息”。来源：当前任务及附件。

### UR-068 — PAWOS 窗口为内容提供安全区，禁止交通灯与 App 内容重叠

- **状态 / 优先级：** `current / P0`
- **Chrome 合同：** 透明标题栏仍覆盖壁纸，但所有 App 的实际内容起点必须避开
  红黄绿交通灯和标题槽位；标题栏不能与 App 自己的页面标题、导航、工具栏、图标
  或正文重叠。标题、辅助文字和工具按钮在窄窗/拖动/缩放时按优先级收缩或隐藏。
- **OS 合同：** 主对话、Files、结果、子 Agent、任务中心等应通过独立窗口分担
  信息密度；不得为了“全都显示”继续压缩成不可读的满屏信息流。
- **原话依据：** “界面混乱问题，还是红黄绿和内容重叠，直接全部都修复”“因为是os，
  之前那种满屏挤压式信息流现在都可以解决了”。来源：当前任务及附件。

### UR-069 — Browser 统一到 ego-browser 控制内核，不保留重复技能与插件链

- **状态 / 优先级：** `current / P0`
- **单栈合同：** 采用 `<ego-lite-repo>` 中 MIT 许可的
  `ego-browser` Agent 控制内核、Snapshot/ref、Task Space、标签页、键鼠、等待、
  上传下载和站点 learnings 机制，取代 PAW 中重复的浏览器 Skill、插件入口和旧控制
  壳；迁移前先证明消费者，迁移后不得同时维护两套同义 Agent 浏览器工具。
- **运行边界：** `ego-lite` 仓库不包含闭源 ego lite 浏览器本体，因此 PAW 不安装或
  启动第二个 Ego 浏览器进程。PAW 现有受管 Chromium/Profile/CDP 继续持有真实页面、
  Cookie、登录态与历史；PAW 提供与 `globalThis.ego` 等价的受控 bindings/Task Space
  authority，使开源 `ego-browser` 内核直接驱动同一个 PAW Browser target。
- **产品边界：** PAW 继续持有 Session/Room capability、权限、Stop/取消、密钥脱敏、
  下载回执、执行 trace 和结果窗口契约；导入的是浏览器控制实现，不是第二个 Agent
  Runtime、第二个浏览器产品身份或绕过 PAW 治理的任意 CDP 通道。
- **验收合同：** 一个安装后的真实 Session 使用新的单一 Browser Skill，在 PAW Browser
  窗口内创建/复用 Task Space，完成导航、Snapshot/ref、点击、输入、等待和截图；人和
  Agent 看到并操作同一 target。旧插件/重复 Skill 无消费者后删除，构建产物中不存在
  第二套浏览器运行时或扩展安装说明。
- **原话依据：** “我找到一个比较好的项目，就是这个 EgoNight，然后已经克隆下来了。
  你可以看一下他怎么做的，可以直接抄，也可以就是做有机融合吗？”“直接接这个都没
  问题”“这样子的话就可以把我们原来那个浏览器技能和插件工具这些都换成这个，都去掉，
  就不要重复的。”“因为我们有源码，所以就不用从头安装。因为我们本身这个软件就是个
  浏览器，所以内置浏览器也不会占用其他额外资源。”来源：当前任务。

### UR-070 — 人和 Agent 共用可见 Browser，Agent 操作轨迹不能成为黑盒

- **状态 / 优先级：** `current / P0`
- **共同操作合同：** PAW Browser 是人可正常操作的完整可见浏览器，也是 Agent 的
  主要网页执行环境。人可使用标签页、地址栏、页面内容、导航、输入、滚动、上传下载；
  Agent 操作的是同一个窗口、同一 target 和同一页面状态。
- **直接权限合同：** Browser capability 对该隔离 Profile 提供直接执行，不做逐动作
  批准，不保留 observe/co-drive/扩展等待分支；Stop、取消、敏感数据脱敏和结果边界仍
  由 PAW 持有。该权限不扩展到用户日常 Chrome、系统终端或任意文件系统。
- **可观察性合同：** Browser App 保留真实 Ego 执行轨迹：正在进行的动作、目标元素、
  导航/输入/等待/截图等动作类型、完成/失败/停止状态和历史回执均可见；轨迹可收起，
  不覆盖主要网页。动作强调和连线由真实 command/trace 状态驱动，支持减弱动态效果，
  不能用循环装饰动画冒充执行。Session/Room 可将关联 Browser 执行投射到其任务中心
  或卫星窗口，使多 Agent 行为路径可检查，而不是后台黑盒。
- **界面命名：** 用户可见名称统一为“Agent 轨迹”或“Agent 浏览器轨迹”；EgoLite 是底层
  实现和来源信息，不作为主界面的产品概念。
- **原话依据：** “用户是可以操控这个浏览器的。这是浏览器主要是 agent 用。”
  “用户当然要需要在我们那个系统里面能看到这个 Agent 是怎么操控浏览器的……还有看
  浏览器的轨迹这些也要保留，因为不能做成一个黑盒……Room 模式里面的那些卫星窗口，
  主要就是为了让行为轨迹可见。”“Ego 轨迹改为agent轨迹”。来源：当前任务。

### UR-071 — 当前 Agent 对话内直接切换“对话 / 对话轨迹”

- **状态 / 优先级：** `current / P0`
- **信息架构合同：** 对话轨迹不是独立 App，也不是需要先进入轨迹页再重新选择
  Session 的二级流程。每个已打开的 Agent Session 在同一工作面提供两个同级视图：
  左侧默认“对话”，右侧“对话轨迹”；切换始终绑定当前 Session。
- **连续性合同：** 切到轨迹再切回对话时，不丢失当前 Session、对话滚动位置、Composer
  草稿、附件和待处理输入。打开另一个 Session 时默认回到其“对话”视图。
- **轨迹合同：** 对话轨迹按真实时间顺序投射该 Session 的用户/Agent 消息、思考摘要、
  Tool 生命周期与公开回执、Browser 细粒度动作、子 Agent 活动，以及执行、停止、失败、
  恢复等状态。它不另造事件源，不以装饰动画冒充执行，也不把任务中心完整复制一遍。
- **原话依据：** “对话轨迹的显示还是非常重要的……左边是对话，右边就是可以切过去
  显示对话轨迹……现在我就想做成那个 Deepseek Harmony……那就直接一个对话可以通过
  页面切换到对话轨迹。”来源：当前任务。

### UR-072 — 所有 App 窗口必须可独立关闭，方形主题的窗口控件也为方形

- **状态 / 优先级：** `current / P0`
- **窗口生命周期合同：** 每个 PAWOS App 实例都必须消费窗口 authority 的关闭、最小化、
  最大化/还原动作。Terminal 等多实例 App 可分别关闭；关闭后不得留下不可见但仍占用窗口
  身份的幽灵实例，再次启动必须按该 App 明确的新建或恢复合同打开。
- **视觉合同：** 当前默认方形主题下，左上角关闭/最小化/最大化三枚控件也采用方形几何，
  颜色与语义不变。该条取代 `UR-034` 中“macOS traffic lights 保持圆形”的例外；状态点
  和 presence dot 仍可保持圆形。所有 App 逐一检查标题安全区、窄窗文字隐藏、点击命中区
  与内容不重叠。
- **原话依据：** “启动的应用，它是没办法关闭的……命令行启动了四五个……点关闭也关
  不了”“因为我们就是方形风格，所以那个左上角的我关闭最小化和最大化的那个红黄绿的
  按钮也得是方形的。就这些 UI 细节你全部得照顾到。”来源：当前任务。

### UR-073 — 提供可复用的 PAWOS 自举与系统改造 Skill

- **状态 / 优先级：** `current / P1`
- **Skill 合同：** 审计 Tutti 已有的自举/系统说明 Skill 或文档，优先迁移其成熟触发、
  上下文读取和改造流程；若没有可直接复用的包，则创建一个最小原生 Pi Package/Skill。
  Skill 能介绍 PAWOS 的 App、窗口、Session/Room、主题、能力和安全边界，也能把用户对
  整个系统的自然语言修改要求路由到真实项目文档、设置、主题或源码 owner。
- **边界合同：** Skill 不创建第二套 Runtime、配置系统或事件总线，不把架构术语直接塞进
  产品界面，不凭文字宣称安装成功。创建、校验、安装预览、启用和 Runtime 生效必须保留
  独立真实回执；新 Session 才加载新启用的 Skill。
- **原话依据：** “参考那个 tutti 的那个项目，因为他自己的自举介绍自己这个系统也是
  做成了一个文档还是技能？反正我们也得做一个这样子的技能，这样子用户就可以通过描述
  需求来改变整个系统，或者来介绍这个系统怎么用。这个技能甚至可以参考或者抄。”来源：
  当前任务。

### UR-074 — Room 主窗只承载对话，次要信息进入可拖动卫星窗口

- **状态 / 优先级：** `current / P0`
- **信息架构合同：** Room 主窗以对话和当前协作上下文为中心；消息流、任务执行、进度、
  治理、文件与子 Agent 等次要信息按对象打开独立卫星窗口。重复的 Room 标题、重复导航
  条和重复任务内容必须删除或合并，不再把所有信息挤回主窗。
- **窗口合同：** 主窗和卫星窗都由同一 desktop authority 管理，可拖动、缩放、聚焦、关闭
  和恢复；Room 的背景层保持可见并以低强度虚化/信息流动表达协作关系，不能遮住内容。
- **原话依据：** “因为是os，之前那种满屏挤压式信息流现在都可以解决了”“还有界面混乱，
  还是红黄绿和内容重叠”“你完全没有重新设计，有卫星窗口就很多可以变成卫星窗口展示”。
  来源：当前任务及附件截图。

### UR-075 — Agent/Session/Room 界面彻底移除 Agent 头像

- **状态 / 优先级：** `current / P1`
- **视觉合同：** 不再渲染 Agent 头像、Persona 图片或为头像预留空列；身份用文本、状态和

- **原话依据：** “ui还是没改好，要不然不要aagent头像了，彻底去掉”“这样做能平衡界面”。

### UR-076 — 卫星窗口展示真实 Pi 上下文并复用 Codex/Tutti 运行动画

- **状态 / 优先级：** `current / P0`
- **数据合同：** 四个或更多伙伴/子 Agent 窗口必须消费真实 Pi Session/Subagent/Room
  事件、消息、工具生命周期、思考摘要、输入输出和交付状态；不得用静态摘要、玩具数据或
  伪造的“已完成”替代真实上下文。
- **运动合同：** 运行中显示类似 Codex/Tutti 的读取、工具调用、消息到达、完成、失败和
  停止状态动画，动画由真实事件驱动、单次播放、支持减弱动态效果；背景动效不能在输入后
  停止，也不能用循环装饰冒充执行。
- **原话依据：** “四个小框是要看到他们这个对话真实上下文，我不是这种玩具，真实上下文的
  pi我才知道运行是否正确”“就想codex这样子，运行中就有这些动画，包括卫星窗口”“当前的
  app无法拖动”“背景也不会动了”。来源：当前任务及附件截图。

### UR-077 — 新输入必须使旧失败/重试动作失效

- **状态 / 优先级：** `current / P0`
- **状态合同：** 用户提交新输入后，旧回合的失败卡、重试、继续、切换模型和同步入口不得
  继续作为可操作动作；旧失败可以保留为不可操作历史。新的 Session/Run 必须拥有新的
  identity，迟到事件不能重新激活旧回合或覆盖新消息。
- **验收合同：** 覆盖“失败后立刻新输入、迟到失败事件、重试点击、Stop/取消”组合，确认
  对话不会被旧回合重试毁掉。
- **原话依据：** “这些在有新输入就完全不再继续存在了，这些继续存在重试会会直接毁掉对话”。
  来源：当前任务及附件截图。

### UR-078 — App 切换、发送、窗口与背景反馈必须达到 Pi/Tutti 的即时感

- **状态 / 优先级：** `current / P0`
- **交互合同：** 点击 App、Session、Room、对话/轨迹、文件、子 Agent 和 Browser 标签时
  必须立即反映选择与窗口状态；发送后先投影用户消息、Session/Room identity 和运行态，
  后台等待 Provider，不得出现十几秒空白、失败闪现后再弹窗或点击无响应。
- **性能合同：** 记录点击到可见、发送到用户消息可见、首个运行事件、最终答复和背景动效
  恢复的延迟；以 Pi/Tutti 的即时交互为基准，避免阻塞式全量刷新和布局抖动。
- **原话依据：** “点击也切换不了，而且我们输入一句话，十几秒才有反应，pi就反应很快”“大
  问题，很多子页面没有改正”“直接照搬tutti的对话加载，因为那个无任何延迟”“对接pi这些，
  窗口tutti，他没什么延迟，交互很快，瞬间就能看到和反应”。来源：当前任务及附件截图。

### UR-079 — Browser 必须是同窗可用的完整受管浏览器

- **浏览器合同：** Browser App 必须提供真实可操作的标签页、地址栏、导航、页面输入、滚动、
  历史、下载和页面内容，并与 Agent 操作同一受管 Chromium/Profile/CDP target。截图、透明
  命中层、iframe 或 about:blank 假页面只能是迁移过渡，不是最终验收。
- **可观察性合同：** Ego/Agent 轨迹、目标元素、命令结果和失败原因继续在同一 App 或关联
  卫星窗中可见；页面框上方不透明，Browser chrome 与网页内容不混叠。
- **原话依据：** “浏览器都没法使用”“就和ego和tutti一样，首先是一个完整浏览器”“你直接把
  浏览器嵌套进去就行了啊”“而且框上面不能透明”“Browser就用eagolite。就是os里面完整浏览器，
  我也能上网那种”。来源：当前任务及附件截图。

### UR-080 — 对话轨迹保留为真实 trace，不复制成原文聊天

- **数据合同：** “对话 / 对话轨迹”切换继续消费现有真实 reducer、Pi 事件、Browser trace、
  Tool/Subagent/Room activity 和生命周期状态；轨迹展示动作、状态、时间和因果关系，而不是
  再写一份原始聊天全文或制造第二事件源。Pi 导出的网页对话记录和 DeepSeek/Codex 式运行态
  只作为交互参考，不能取代 PAW 数据权威。
- **原话依据：** “对话轨迹我们有这个功能的，不是让你写原文，而是trace。你看看deepseek的

### UR-081 — Composition 8 使用完整 Image 2 原画底图与稀疏矢量特效

- **视觉合同：** 先用用户原图通过 Image 2 处理为一张完整、可全屏 cover 的静态底图；静止时
  应基本接近原画。只在互不重复的少量区域叠加可复用、可关闭、由音乐/事件驱动的稀疏矢量
  动效，禁止把同一几何对象一半当 raster、一半再矢量化，也禁止大规模矢量堆叠破坏美感。
- **原话依据：** “Composition 8你先用iamge2进行处理呀，现在太乱了，我们矢量化的图失去了美感”

  都是全屏的”“可以动的矢量没看到了”。来源：当前任务及附件图片。

### UR-082 — structured_output 与子 Agent 失败必须经真实 Schema 校验

- **状态 / 优先级：** `current / P0`
- **Provider 合同：** 发送给 Provider 的 `structured_output` 必须是合法、可序列化的 JSON
  Schema/工具参数对象；不能把字段名数组、布尔值放到错误层级，也不能让 malformed persisted
  schema 直接穿过 delegation/runtime。无效请求应在创建子 Agent 前明确显示可恢复错误，并
  保留原始上下文，不自动反复重试。
- **验收合同：** 覆盖 `['buildCommands','testCommands','configFiles']`、`False`、缺少
  type/required、嵌套 properties、旧持久化 schema 和 token budget exceeded；界面须显示
  哪个边界失败以及下一步，而不是伪造子 Agent 成功。
- **原话依据：** “token budget exceeded”“Codex error: Invalid schema for function
  'structured_output': [] is not of type 'object', 'boolean'”“subagent太多失败了”。来源：
  当前任务及附件截图。

### UR-083 — 所有 App 按真实纵向功能完成后再统一验收

- **交付合同：** Agent、Browser、Room、Files、Terminal、Memory、Knowledge、Input、Planning、
  App Center、Monitor、Settings 等每个 App 都要逐项接通真实能力、窗口生命周期、窄窗布局、
  滚动、菜单、动画、错误恢复和 satellite 投影；不得只完成 Agent 的外观后把其他页面继续留
  成旧网页/静态 demo。
- **测试节奏：** 所有功能和 UI 纵向切片完成后，统一执行一次集中测试、typecheck/build、安装、
  前台交互、Browser/Terminal/Room/Session 多窗和性能验收；在此之前的检查只说明局部回归，
  不代表产品完成。
- **原话依据：** “问题太多了，现在你一个app都没做好，做完，其他比如知识库，还是网页”“当前
  很多功能都是有实现的”“全部功能完成之后，再统一进行一次测试就行”“每个app都要注意”。来源：
  当前任务。

### UR-084 — 优先直接迁移成熟源码，避免防御性过度设计

- **状态 / 优先级：** `current / P0`
- **实现合同：** Tutti、EgoLite 和 Codex/Codexx 已有可用前端或 Runtime 实现时，优先迁移
  完整纵向切片并在 PAW 的既有 authority/transport seam 上做薄适配，不重写同等能力，也不为
  尚未出现的异常建立新框架。只保留真实触发过的输入校验、生命周期和恢复防线。
- **兼容边界：** 可直接复用源码不等于伪造宿主能力。Electron `<webview>`、EgoLite 开源 CDP
  harness 与 PAW 当前 Swift/WKWebView 宿主之间只补必需的宿主接口；不能用截图桥冒充原生同窗
  Browser，也不能因为宿主不同复制第二套 Browser state/Agent Runtime。
- **原话依据：** “反正tutti和egolite还有codexx前端都可以直接把代码拿过来”“不要防御性编程
  过度设计”“现在功能我都推荐直接抄”。来源：当前任务。

### UR-085 — 长对话采用 Codex 式分层折叠，内容增多仍保持稳定

- **状态 / 优先级：** `current / P0`
- **信息层级合同：** 用户与 Agent 的主消息正文保持连续阅读；同一轮中的长思考、Tool 调用、
  运行日志、子 Agent 活动和重复进度按真实事件组进入可多级折叠的 disclosure，不把所有中间状态
  默认平铺到时间线。
- **连续性合同：** 展开或收起只改变投影状态，不删除真实 trace、不复制原文聊天、不改变事件
  顺序；长轮次、嵌套 Tool 和多次展开/收起后仍保持当前 Session、滚动与 Composer 草稿稳定。
- **迁移合同：** 优先直接迁移 Codex/Tutti 已成熟的 turn/activity disclosure 结构，在 PAW 现有
  reducer 事件上做薄适配，不新建第二套对话状态机。
- **原话依据：** “codex的对话就是大了内容多次折叠就不会乱”。来源：当前任务。

### UR-086 — Browser 必须提供真实 History 与 Settings，不使用空白 Chrome 内部页

- **状态 / 优先级：** `current / P0`
- **历史合同：** Electron `<webview>` 不具备完整 Chrome 内部 UI，Browser 不得用
  `chrome://history` 白页冒充历史。PAW Browser 必须展示同一固定 Browser Profile 的真实访问
  记录，支持搜索、重新打开、删除单条和清空，并保留标题、URL 与访问时间。
- **设置合同：** Browser Settings 必须操作同一 `persist:paw-browser` Session 的真实浏览数据，
  只展示已接通的启动页、下载、Cookie/站点数据、缓存或权限动作；清理类操作需要明确目标、确认和
  成功/失败回执，不显示无效开关，也不导航到 `chrome://settings` 空页。
- **同一浏览器合同：** History/Settings 是 Browser App 内置 surface；普通网页仍由人和 EgoLite
  共用的同一个可见 guest/target 承载，不能为管理页启动第二个浏览器或复制 Browser authority。
- **原话依据：** “设置历史这些都没有”，并附当前 Browser 打开 `chrome://history/` 后白屏截图。
  来源：当前任务及附件截图。

### UR-087 — 整个 PAWOS 使用精心校准的字体层级与阅读尺度

- **状态 / 优先级：** `current / P0`
- **字体合同：** 保留产品已有 SF Pro Text/Display、系统字体与 PingFang SC 等中英文字体回退，
  不为装饰引入第二套字体；代码、路径、时间与技术标识才使用 SF Mono。
- **层级合同：** OS 状态栏、窗口标题、App 导航、页面标题、正文、Composer、按钮/输入、状态标签、
  元数据、trace 与代码输出使用少量明确的语义字号/行高/字重角色。禁止继续散落 8–12px 的任意值，
  也不能用一条全局缩放把所有内容一起压小或放大。
- **阅读合同：** Agent/Room 正文维持舒适行高与约 45–75 个字符的阅读宽度；窄窗口、长中英文标题、
  系统缩放与字体回退时不重叠、不截断关键操作，紧凑元数据仍保持可读。
- **原话依据：** “整个os的字体和大小都要精心调节”。来源：当前任务。

### UR-088 — Browser 前台达到完整浏览器基线，并由 EgoLite 控制同一页面

- **状态 / 优先级：** `current / P0`
- **前台合同：** 网页内容占据 Browser 主体；顶部提供真实多标签、地址栏、前进/后退/刷新和
  浏览器菜单。Agent 轨迹是可收起的观察层，不得长期挤压正常上网空间。
- **菜单合同：** 只展示已经接通的真实动作，至少覆盖页内查找、打印、页面缩放、截图、下载、
  清除浏览数据和 Browser Settings；有现成 EgoLite/Electron 能力时接入设备模拟，否则不显示
  假入口。不得使用空白 `chrome://` 页面冒充这些功能。
- **共同控制合同：** 用户通过这套完整 Browser chrome 操作的页面，就是 EgoLite/Agent 通过
  exact `targetId` 控制和产生 Agent 轨迹的同一个可见 guest。
- **原话依据：** “就这种完整浏览器就行，配合上egolite的控制，就天下无敌”，并附完整浏览器
  标签栏、地址栏与菜单参考截图。来源：当前任务及附件截图。

### UR-089 — Memory 是第二大脑，并提供可保存的记忆偏好页

- **状态 / 优先级：** `current / P0`
- **产品合同：** Memory App 不能只是记录列表或调试视图；它是用户管理第二大脑的完整 App，现有
  时间线、图谱、搜索、详情与治理能力需要在同一信息架构中精心排布，并保持真实数据来源。
- **偏好页合同：** Memory 增加独立的“记忆偏好”页面，让用户明确指定应优先记住、弱化或避免
  记住的内容类别，以及记忆整理/召回所需的既有可配置偏好。页面只展示 Runtime 已有或本次真实
  接通的配置；修改必须保存到单一权威存储，重新打开仍能读取，并给出成功、失败与恢复回执，不能
  用仅存在于前端 state 的假开关冒充完成。
- **体验合同：** 偏好页面与 Memory 的其他页面共享统一导航、字体、窄窗与滚动规则；敏感信息、
  删除或清空类动作保持明确说明与确认，但不为未出现的场景增加防御性流程。
- **原话依据：** “记忆app精心调整，还有增加一个页面，因为这个记忆相当于第二大脑，用户可以在
  这个页面指定记忆的偏好”。来源：当前任务。

### UR-090 — PAWOS 顶部栏控件、品牌与 App 标题不得重叠

- **状态 / 优先级：** `current / P0`
- **布局合同：** 顶部系统栏中的窗口控制、PAWOS 品牌和当前 App 标题使用互不覆盖的布局槽；不能

### UR-208 — Memory 以时间线和日记为核心的个人记忆整理小管家

- **状态 / 优先级：** `current / P0 personal memory experience`
- **真实需求：** Memory 首页改为以个人时间线为首要入口；每日/日记的显示与
  活动分布须被重新优化，并以美观、整齐、可持续查看为直接用户体验目标。窄宽
  窗口也不得以错误换行、溢出或挤压破坏日记、活动分布和对话的可读性。用户必须
  能从日记或时间线原地与 Memory 管家 Agent 对话，围绕最近 idea、未完成事项、
  心情、下一步建议和安排提问，也可以问任何问题。该面向用户的定位是“个人记忆
  整理小管家”，而不是仅展示后台整理队列或技术指标的管理页。随附截图中的活动
  分布是本条的明确优化对象。Memory 偏好控件应真实可修改；Memory 与 Knowledge
  的加载/恢复要可继续且可说明，不能把短暂加载失败伪装成空数据。
- **最新控制修正：** 首屏中部应是画布：展示真实整理结果中的今日/最近内容，
  或当前 Agent 在有证据时判断最值得向用户展示的内容；不能继续把所有管理控件、
  日记细节、活动分布、日历和聊天平铺在中部。日记/活动/日历与聊天入口应下沉到
  下方或次级入口。此前“首页换成时间线”继续约束首页的组织语义和
  可达内容，但不再被解释为“中部只能是完整时间线列表”。
- **原话歧义边界：** “设置可以专门agent完成这个”在当前工作语境中按“可以设置/
  分派专门 Agent 完成这项画布工作”执行；本句不单独授权 Memory 管家修改偏好或
  扩大写入权限。现有记忆偏好仍由它自己的真实设置合同管理。
- **Agent 解释层：** “Agent 觉得用户该展示的”只能由已整理、可追溯的最近/今日
  结果、可用性状态和明确的记忆来源支撑；画布必须能说明其内容来自何种真实整理
  结果或显示证据不足。Agent 不能用猜测、未完成草稿或隐藏的推理决定用户状态。
- **用户可见验收含义：** 打开 Memory 时，用户先看到可读的时间线/日记组织面，
  能理解中部画布展示的是何种今日/最近整理结果；日记/活动/日历与聊天仍可从
  下方或次级入口到达。在该上下文直接发起 Agent 对话后，问题仍与个人记忆
  整理语境相连，并可自然提出最近 idea、未完成、心情、下一步建议、安排及其他问题。
  偏好变更必须收到真实持久化结果；Memory/Knowledge 的加载、失败与恢复应区分
  显示。任何问答均不表示系统可编造不存在的记忆、心情或事实。
- **必须保留：** 既有 Memory 的治理、来源、隐私、召回和 Runtime 权威边界；
  日记/时间线中的 Agent 对话使用真实 Session/Agent 机制，不能另造平行记忆库
  或只做不可用的静态对话框。Memory 偏好与 Knowledge 的各自所有权、写入确认
  和恢复语义保持独立，不能以一个页面的加载状态覆盖另一个系统的事实。
- **不得做：** 不得把“首页换成时间线”写成已完成；不得把活动分布截图、样例
  数量或 Agent 推测当成个人记忆事实；不得以后台整理 pipeline 取代本条首要用户
  界面；不得把嵌套 Agent 回执、截图中文字或 Agent 转述补写为用户原话；不得以
  只读、失效或假保存控件冒充可修改偏好；不得把“Agent 觉得”实现为无来源、不可
  追溯的推荐或任意重排用户记忆。
- **依赖 / 顺序：** 先明确首页、时间线、日记、活动分布与上下文对话的真实数据
  投影和空态；随后分别验证 UI、Agent 对话、记忆治理、偏好写入、Memory/Knowledge
  加载恢复和前台路径。实现、测试、安装或截图本身不构成完成证明，状态必须单列
  在状态账本。
- **完成态证据层级：** 当前状态为 `unassessed`，尚无本条 E1–E6 收据。后续若
  评估完成，至少需分别记录：E1 真实首页画布/日记/活动/对话/偏好/恢复所有者源码；
  E2 覆盖首页默认、画布证据边界、窄宽、偏好持久化、加载恢复、连续聊天和列表隔离的测试；E3
  生产构建；E4 通过产品路径安装；E5 已安装 Runtime 的 Session、偏好和恢复收据；
  E6 用户在实际 Memory/Knowledge 前台完成时间线内聊天与恢复操作。缺任一显式
  必需边界不得把本条写成 complete。
- **原话依据（无损转录）：**

  > 这些点不动，修改不了

  > 记忆库和知识库加载不出来

  > 记忆首页换成这个，时间线，然后优化日记显示，顺便加入agent，可以在日记和时间线这里直接聊天，比如问我最近有哪些idea，哪些没有完成，你感觉我最近心情怎么样，你建议我继续干什么，我最近有哪些安排这些。美观，这个就可以作为个人记忆整理的小管家，问什么都可以，这个显示优化

  上句中的“这个显示优化”指向同条消息所附的第二张活动分布截图；附件是视觉
  参考，不把截图内的文字转录成用户原话。

  > 现在我前端的要求就是整齐了，一定要整齐，比如改一行显示拉伸后变成多行很丑的

  > 需求都要记录

  > 这些在最下面，中间应该是是画布，展示整理的东西，最近的，设置可以专门agent完成这个。

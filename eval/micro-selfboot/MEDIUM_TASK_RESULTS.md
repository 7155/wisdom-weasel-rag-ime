# 中等任务：已测量，尚无完整交付收益

2026-09-06。任务是一个持久的 Lab 事件账本：原子 JSONL 存储、报告与 CLI、真实 Pi Host 关闭后追加 callId 去重需求。三阶段、20 条实现检查、4 条实际交付检查。模型代码约为几个模块的中等编码任务；它不是 20 个独立业务任务。

一组配对，共用同一空实现、任务、Luna low 与验收器。单 Session 保留私有历史；Room 由存储、报告和整合伙伴依次接力，不声称测了并行加速。两个策略先在每臂 100k 观察 tokens 时停止，随后从原产物继续，累计上限统一为每臂 300k / 30 条模型响应。这两个预算阶段仍是一组任务配对，不是多次独立成功率试验。

| 观测 | 单 Session | Room |
| --- | ---: | ---: |
| 完整任务交付 | 0/1 | 0/1 |
| 最终实现检查 | 16/20 | 16/20 |
| 实际交付检查 | 0/4 | 0/4 |

| 两次运行的执行时段合计 | 201.752 秒 | 268.452 秒 |

两侧都在在途请求中越过观察阈值；未记录的在途用量、Provider 实际账单未知。费用只报告已知估算。执行时段不包含两次运行之间等待恢复的墙钟间隔，也不作为稳定性能结论。

两侧剩余失败均包括 CLI 无效输入后的空库导出，以及 callId 去重、冲突和非法身份处理。Room 走到了追加需求，但没有完成整题，因此不能写成“复杂任务成功率提升”或“断点恢复后完成”。单例与当前资源配置也不能用来推断多 Agent 无效。

父验收重新核对了 **5 个阶段的精确 turn 绑定、模型响应数、用量与原 transcript 前缀 hash**。继续同一 Session 会追加 transcript；按前缀核验历史回执，不能拿后来全文件 hash 否定原来的合法快照。两个预算阶段的 task hash 与 seed hash 完全相同。

复核还发现旧交付验收器最后一次 CLI replay 会写入候选库。原交付结果仍全部失败，未升级为成功；相关目录只保留为历史诊断产物。验收器现已在工作区副本上执行回放，回归验证不会再修改原候选产物。没有用修复后的验收器重跑模型或重评分制造收益。

此前 SQLite 版是另一道受阻题：首轮没有工具目录的无效运行、第二轮 WorkspaceHarness 禁止 `.sqlite/.db` 的观察均保留，不混进 JSONL 对照。新题使用真正的文本 JSONL 与文件原子替换，没有变更或绕开数据库敏感文件策略。

回执位于本机 `EvaluationArtifacts/medium-jsonl-20260906/` 与 `medium-jsonl-continued-20260906/`。后者的 `parent-reconciliation.json` 绑定 5 个 turn；`solo/report.json`、`room/report.json` 保留最终失败。OS Lab 的“PAW 协作与接续”同时列出这轮中等题与旧 SQLite 阻塞记录，图示不将接续进入冒充任务通过。

当前可以用于正向量化的优化仍是 [Room 整合优化](OPTIMIZATION_RESULTS.md)：保持 3/3 检查，调用 3→2、tokens 降低 35.49%、估算成本降低 24.70%。它与本中等任务不是同一数据集，不能合并为中等任务收益。

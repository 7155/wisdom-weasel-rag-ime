# 智鼬 Agent 记忆与协作视觉系统

- 产品定位：以 Agent 为核心的个人记忆与协作工作台；输入法只是记忆来源之一
- 品牌承诺：记得你，也陪你做事
- 设计方向：纸张阅读面 + 系统控制层
- 信息密度：8/10
- 动效强度：4/10
- 适用页面：全局壳层、Session、Room，以及复用基础组件的治理/知识页面

## 设计原则

1. 聊天和长文本是主角，主工作区必须占满可用高度。
2. 纸张只用于阅读层；导航、状态栏和工具区使用低饱和系统底色。
3. 青绿色只表达当前选择、主要动作和运行焦点，不大面积铺色。
4. 状态必须同时包含文字或图标，不依赖颜色单独传达。
5. 不使用发光、彩色渐变、弹簧回弹、连续装饰动画或大面积玻璃拟态。
6. 普通对话与多人协作共用同一套壳层、面板、消息、输入框和动效语言。这套共享规则写在
   `src/design/workspace.css`，同时对 `.agent-*` 与 `.room-*` 选择器声明，两侧不得各写一份。
7. 主界面只说用户意图和结果：对话、任务、伙伴、验证、停止、继续。`Runtime`、`Kernel`、`Root`、`Dispatch`、`Session`、回执 ID 等实现术语只出现在展开后的技术详情与诊断页。
8. 同一动作只保留一个主要入口；低频归档、删除与技术配置进入“更多”或设置，不和当前主任务争夺注意力。
9. 错误状态必须给出下一步：重试、继续、返回、换模型、查看原因或停止，不能只展示内部错误码。
10. `智鼬` 只是默认称呼，不是不可修改的产品常量。应用名称、未指定具体伙伴时的通用称呼和侧栏短句由同一份本机设置管理；保存后同步更新壳层、窗口标题和通用文案。
11. 全局称呼与具体伙伴名字分开归属。前者不改写伙伴档案；用户创建的伙伴可直接重命名，内置伙伴先基于原设定创建自己的版本，避免历史对话被静默改名。

## 色彩

中性色为暖纸调（warm greige），不带绿灰倾向；青绿只作为强调色出现。

| 角色 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| Canvas | `#E9E5DD` | `#16150F` | 应用背景；管理页在其上放卡片 |
| Chrome | `#F2EFE8` | `#1C1B16` | 导航、列表、状态面板 |
| Paper | `#FDFBF6` | `#201F19` | 聊天和文档阅读面 |
| Surface | `#FFFEFB` | `#24231D` | 控件、卡片、输入框 |
| Text | `#1B1A15` | `#F2EFE7` | 主要文字 |
| Secondary | `#4E4A41` | `#BCB6A9` | 辅助文字 |
| Border | `#DDD6C8` | `#3D3A31` | 分隔与控件边界 |
| Accent | `#066D63` | `#57BCAF` | 当前项、主要动作、焦点 |
| Info | `#2A67AB` | `#89AED6` | 用户消息、信息提示 |
| Success | `#17795A` | `#74C898` | 完成 |
| Warning | `#8F5502` | `#E0AE62` | 等待、审阅 |
| Danger | `#BB3C4C` | `#EF8A91` | 失败、破坏性操作 |

所有组件只引用语义 token，不在组件中新增品牌色。`--color-text-primary`、`--color-surface-muted`、
`--shadow-control`、`--shadow-focus` 等别名 token 在 `tokens.css` 中统一定义；组件不得再写
`var(--x, #hex)` 形式的硬编码兜底色。

层次由 `--shadow-1 / --shadow-2 / --shadow-3` 三档表达：1 为静止卡片，2 为抬起或悬停面，
3 为浮层。命名阴影（menu / dialog / composer）都映射到这三档。

## 字体

- 全系统统一使用系统 `SF Pro Text` / `PingFang SC`；拉丁字符不得由中文字体抢先渲染，并统一使用 400 / 500 / 600 / 700 四档字重。
- 标题与结构标签沿用同一字体栈，只使用轻微负字距和 600–700 字重形成层级，不另建展示字体。
- Agent 与 Room 聊天正文统一为 15px / 1.66；管理页和长文档基准为 16px / 1.68。纸张感由版式和材质表达，不通过切换衬线字体制造。
- 代码和运行标识：`SF Mono` / `Menlo` / `Consolas`。
- 辅助文字不得小于 12px；全局 UI 类型角色固定为 Caption 12px、UI 13px、UI Strong 14px、Body 16px。
- 除代码等宽字体外，不允许组件或页面另建字体风格。

## 空间与形状

- 基础间距：4px；常用间距 8 / 12 / 16 / 24px。
- 圆角：4 / 6 / 8px；只有头像、状态点和发送按钮使用全圆。
- 面板层级主要靠 1px 边框和底色区分；阴影只用于卡片（`--shadow-1`）、浮层、输入框和对话框。
- 管理页统一结构：页面坐在 Canvas 上，`.mgmt-section` 是 Surface 卡片；卡片内的整宽内容
  （指标、列表、表格）做成带边框的内嵌块，不允许出血到页面边缘。
- 桌面端阅读区不使用固定最大高度；高度来自 `100dvh`。

## 工作台布局

- 全局顶栏为 56px，工作区内部结构栏为 48px；品牌、列表、聊天和状态标题共用同一底色与基线。
- 聊天结构栏以约 62% 不透明度的 Paper 覆盖在全高时间线上，配合 12px 背景模糊形成层次，不再从时间线中扣除一行高度。
- 时间线顶部必须提供不小于悬浮结构栏的 header space；首条内容不得被遮挡，滚动内容允许从半透明结构栏下方经过。
- 主导航、任务列表、状态面板支持拖动、键盘方向键调整、双击复位和本地持久化。
- 普通对话与多人协作的左右面板默认宽度一致：224px / 312px。
- 小于或等于 1360px 时状态面板统一改为抽屉；小于或等于 760px 时列表和状态均为覆盖层。进入窄断点时，桌面已展开的面板自动收起，避免突然遮住聊天。
- 聊天输入框浮在时间线底部，整条底托透明；只允许输入框本体使用半透明和背景模糊。
- 时间线必须保留等于或大于输入框高度的 footer space，保证最后一条消息不被覆盖。

## 动效

- 按下：90ms，向下位移 1px，并使用内阴影。
- 悬停：140–180ms，只改变底色、边框和短阴影。
- 菜单/Popover：180ms，从上方 3–4px 淡入。
- 面板：220ms 沿来源方向进入；关闭速度不慢于打开。
- 消息：180–220ms，从下方 4px 淡入，不使用列表级联和弹簧回弹。
- 展开区：220ms 网格行展开 + 140ms 透明度。
- 拖动期间禁用布局过渡，避免输入和指针发黏。
- 必须尊重系统 `prefers-reduced-motion` 和应用“减少动效”选项。

## 组件规则

### 按钮

- 主要动作使用 Accent 实色；普通按钮使用 Surface + Border；安静按钮透明。
- 图标统一使用 Lucide，图标按钮必须提供可访问名称。
- 桌面密集工具栏最小 32px；移动端紧凑工具栏至少 40px，发送、主操作等关键目标至少 44px。

### 输入框

- 输入框本体为半透明 Surface，`backdrop-filter: blur(14px) saturate(115%)`。
- 聚焦时上浮 1px，并显示 Accent 边框与可见焦点光环。
- 中文输入法组合输入期间不得触发 Enter 发送。

### 菜单和弹窗

- 使用 Paper/Surface 底色、1px 边框和短方向性阴影。
- 不使用全屏模糊背景；遮罩只降低背景对比。
- 打开后聚焦进入，Escape 关闭，并避免键盘陷阱。

### 状态和消息

- 用户消息使用 Info-soft；Agent 正文直接排版在 Paper 上。
- 工具、计划、附件和审批使用结构化卡片，不模拟普通聊天气泡。
- 运行、等待、失败必须有图标和文字标签。

## 可访问性和性能验收

- 正文对比度至少 4.5:1，焦点状态清晰可见。
- 所有拖动分隔条具有 `role="separator"`、当前值和键盘操作。
- 导航较长时提供“跳到主工作区”链接。
- 375 / 768 / 1024 / 1440 / 1600px 下不得出现页面级横向滚动。
- 长消息列表保持虚拟化；拖动不触发 React 高频重渲染。
- 不隐藏滚动内容在固定输入框后面。
